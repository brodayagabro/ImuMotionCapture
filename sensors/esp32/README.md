# Прошивки ESP32

В этой папке находятся две взаимозаменяемые рабочие прошивки и одна
диагностическая для системы из ESP32, мультиплексора TCA9548A и датчиков IMU.
Одновременно на контроллер загружается только одна из них.

Выбирайте рабочую прошивку по значению регистра `WHO_AM_I` (`0x75`), а не
по I2C-адресу устройства:

| `WHO_AM_I` | Датчик | Прошивка |
|---:|---|---|
| `0x68` | MPU-6050 | `DMP_with_TCA9548A_udp/` |
| `0x70` | MPU-6500 | `MPU6500_with_TCA9548A_udp/` |

Это два разных числа с разным назначением. Например, MPU-6500 отвечает на
I2C-адресе `0x68`, но возвращает `0x70` из регистра `WHO_AM_I`.
TCA9548A в текущей сборке также имеет I2C-адрес `0x70`, однако находится на
основной шине, а датчики — за его отдельными каналами.

## `DMP_with_TCA9548A_udp/`

Основная прошивка системы захвата движений. Она:

- обнаруживает до пяти MPU6050 на каналах TCA9548A;
- получает кватернионы из DMP датчиков;
- принимает команды управления по UDP;
- передаёт один согласованный `FRAME` со всеми доступными кватернионами;
- поддерживает запуск, остановку, калибровку и изменение частоты потока.

Главный скетч — `DMP_with_TCA9548A_10HZ_upd.ino`. Несмотря на историческое
`10HZ` в имени, частота меняется командой `SET_RATE` в диапазоне 1–100 Гц.
Подробное описание протокола и команд находится в README внутри каталога.

Физический маппинг каналов: `7/6` — левая рука, `2` — корпус, `1/0` —
правая рука.

Используйте этот вариант только для MPU-6050 с `WHO_AM_I=0x68`. Для него
нужны I2Cdevlib и `MPU6050_6Axis_MotionApps20`.

## `MPU6500_with_TCA9548A_udp/`

Основная прошивка с тем же внешним UDP-интерфейсом для MPU-6500 с
`WHO_AM_I=0x70`. Она читает сырые данные датчиков напрямую и вычисляет
кватернионы отдельным фильтром Mahony из файлов `MahonyFilter.h/.cpp`.
DMP, FIFO и I2Cdevlib не используются.

Частота фильтра фиксирована на 100 Гц, а частота UDP-кадров независимо
настраивается командой `SET_RATE` от 1 до 100 Гц. Калибровка
акселерометров и гироскопов сохраняется в NVS ESP32 по физическому каналу
TCA9548A.

Формат `FRAME/Q`, UDP-порт `4210`, команды и маппинг каналов полностью
совместимы с вариантом MPU-6050 и приложением на компьютере. Подробности
калибровки и фильтра находятся в README внутри каталога.

## Настройка Wi-Fi

Реквизиты локальной сети не хранятся в репозитории. Перед сборкой основной
прошивки выполните в выбранном каталоге:

```bash
cp wifi_secrets.example.h wifi_secrets.h
```

Откройте `wifi_secrets.h` и укажите свои значения:

```cpp
static const char *WIFI_SSID = "имя сети";
static const char *WIFI_PASSWORD = "пароль сети";
```

`wifi_secrets.h` добавлен в локальный `.gitignore`. В коммиты должен попадать
только безопасный `wifi_secrets.example.h`.

Для обеих рабочих прошивок нужны ESP32 Arduino core и `AsyncUDP`.
I2Cdevlib с `MPU6050_6Axis_MotionApps20` требуется только варианту
MPU-6050.

## `scan_bus_web/`

Диагностическая прошивка для проверки уже собранной системы. Она сканирует
основную I2C-шину, проверяет TCA9548A по адресу `0x70`, а затем последовательно
сканирует все восемь каналов мультиплексора.

Сканер не использует домашнюю или лабораторную Wi-Fi сеть. После загрузки
ESP32 создаёт открытую временную точку доступа:

```text
ESP32C3_I2C
```

Порядок проверки:

1. Загрузите `scan_bus_web/scan_bus_web.ino` в ESP32.
2. Откройте Serial Monitor на скорости 115200 бод.
3. Подключитесь с компьютера или телефона к сети `ESP32C3_I2C`.
4. Откройте адрес, напечатанный в Serial Monitor. Обычно это
   `http://192.168.4.1`.
5. Нажмите «Сканировать шину» или включите автообновление.

При исправном соединении основная шина должна видеть TCA9548A по адресу
`0x70`. На каждом занятом канале должен обнаруживаться датчик, обычно по
адресу `0x68`, реже `0x69`. Этот сканер показывает только I2C-адрес и не
различает MPU-6050 и MPU-6500 по `WHO_AM_I`. Пустые каналы выводятся как
`NONE`.

Точка доступа открытая, поскольку прошивка предназначена только для временной
стендовой диагностики. После проверки загрузите обратно основную UDP-прошивку.
