# MPU6050 ×5 через TCA9548A: UDP-сервер и визуализатор

Проект состоит из двух частей:

- `DMP_with_TCA9548A_10HZ_upd.ino` — скетч ESP32-dev module/ESP32-C3(C6), который читает до пяти MPU6050 через TCA9548A, принимает команды по UDP и отправляет кватернионы;
- `mpu_udp_viewer.py` — настольное Tk/Matplotlib-приложение с пятью 3D-кубами, назначением датчиков и монитором сырых пакетов.

## Настройка и прошивка ESP32-C3

Перед прошивкой проверьте в начале скетча:

```cpp
static const char *WIFI_SSID = "...";
static const char *WIFI_PASSWORD = "...";
static const uint16_t UDP_LISTEN_PORT = 4210U;
```

Устройство работает как UDP-сервер в режиме Wi-Fi station. После загрузки откройте Serial Monitor на скорости **115200 бод**. Когда ESP32 подключится к сети, появятся строки:

```text
NET:IP 192.168.x.x
NET:UDP_PORT 4210
NET:UDP server 192.168.x.x:4210
```

Для сборки нужны ESP32 Arduino core (библиотеки `WiFi` и `AsyncUDP` входят в него), а также `I2Cdev` и `MPU6050_6Axis_MotionApps20` из I2Cdevlib. Целевая плата — ESP32-dev module/ESP32-C3(C6).

## Запуск приложения

В директории проекта уже создано виртуальное окружение `.venv`. Запуск:

```bash
source .venv/bin/activate
python mpu_udp_viewer.py
```

Если окружение нужно пересоздать:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

В приложении:

1. Введите IP, напечатанный ESP32, и порт `4210`.
2. Нажмите **«Подключиться»**. Приложение отправит `HELLO` и `STATUS`; устройство запомнит IP и локальный UDP-порт клиента.
3. Нажмите **START**.
4. Для каждого куба укажите номер управляющего датчика. По умолчанию кубы 1…5 связаны с датчиками 1…5.
5. Справа отображается полное содержимое каждого принятого и отправленного пакета.
6. Частоту можно изменить в диапазоне 1–100 Гц. Практический максимум зависит от пяти датчиков, I²C и времени обработки одного кадра.

Кнопка **«Отключиться»** закрывает только сокет приложения. Чтобы остановить поток на ESP32, сначала нажмите **STOP**.

Для `CALIB` все датчики должны лежать неподвижно. Калибровка выполняется в основном цикле и временно приостанавливает поток.

Если ответы не приходят, проверьте, что компьютер и ESP32 находятся в одной сети, что в гостевой Wi-Fi не включена изоляция клиентов и что локальный firewall разрешает входящие UDP-ответы приложению.

## UDP-протокол

ESP32 слушает команды ASCII на порту `4210`. Любая принятая команда регистрирует её отправителя как текущего клиента. Поток отправляется только одному — последнему зарегистрированному — клиенту.

Поддерживаемые команды:

```text
HELLO
PING
START
STOP
STATUS
GET_CONFIG
CALIB
SET_RATE <1..100>
```

Один кадр передаётся одним UDP-датаграммом:

```text
FRAME <sequence> <millis> <quaternion_count>
Q <sensor_id> <w> <x> <y> <z>
Q <sensor_id> <w> <x> <y> <z>
...
```

Пример:

```text
FRAME 1842 93215 5
Q 1 0.998412 0.012300 -0.044100 0.031200
Q 2 0.704100 0.003100 0.710000 -0.002000
```

Компоненты передаются в порядке `w x y z`. Serial сохраняет прежний построчный формат:

```text
quat <sensor_id> <w> <x> <y> <z>
```

UDP не гарантирует доставку: редкая потеря кадра допустима, а следующий кадр содержит актуальное состояние всех доступных датчиков.


В случае отсутствия возможности запуска приложения на python общение с модулем можно производить с помощью утилиты nc:

```bash
nc -u 192.168.1.X 4210
```
