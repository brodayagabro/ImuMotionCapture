# Human_spine_UDP.blend

Итоговый Blender-проект принимает кватернионы пяти MPU6050 напрямую по UDP и двигает риг `Human_Rig`.

## Файлы

- `Human_spine_UDP.blend` — очищенный итоговый проект Blender 4.0;
- `udp_mocap.py` — исходник скрипта, также встроенный в `.blend` как Text Block;
- `build_udp_blend.py` — воспроизводимая сборка `.blend` из исходного `.blend1`;
- `Human_spine_N_sensors.blend1` — исходный файл, оставленный без изменений.

Из итогового файла удалены дубли старых Serial-скриптов и неиспользуемая стандартная кость `Bone`. Сохранены арматура, камера, свет и Scripting workspace.

## Физическая схема

| Канал TCA | ID текущего контроллера | Сегмент | Кость Blender | Родитель |
|---:|---:|---|---|---|
| 0 | 1 | левое плечо / верхняя часть руки | `shoulder.L` | спина |
| 1 | 2 | левое предплечье | `forearm.L` | левое плечо |
| 2 | 3 | спина / корпус | `spine` | neutral frame |
| 6 | 4 | правое предплечье | `forearm.R` | правое плечо |
| 7 | 5 | правое плечо / верхняя часть руки | `shoulder.R` | спина |

Драйвер автоматически распознаёт оба встречающихся формата: физические номера
каналов `0,1,2,6,7` и последовательные ID `1,2,3,4,5`, которые сейчас выдаёт
контроллер `192.168.1.117`. Внутри рига оба формата приводятся к каналам TCA.

Спина вращает всю верхнюю часть и руки через иерархию рига. Плечо вычисляется относительно спины, а локоть — относительно соответствующего плеча. Перед установкой в `rotation_quaternion` поворот переводится в rest-систему координат конкретной кости.

## Запуск

1. Прошейте ESP32 и узнайте IP в Serial Monitor, 115200 бод.
2. Откройте `Human_spine_UDP.blend`.
3. Перейдите в workspace **Scripting**. Текст `udp_mocap.py` уже выбран.
4. В начале текста задайте:

   ```python
   DEVICE_IP = "192.168.1.117"
   DEVICE_PORT = 4210
   ```

5. Примите описанную ниже N-позу.
6. Нажмите **Run Script**. Скрипт отправит `HELLO`, `STATUS`, `SET_RATE` и `START`, после чего захватит один согласованный neutral frame всех пяти сенсоров.
7. Откройте Text Block `UDP_MOCAP_STATUS` или системную консоль Blender для диагностики.

ESP32 отправляет поток только последнему UDP-клиенту. Если после Blender подключить `mpu_udp_viewer.py` или `nc`, поток перейдёт к ним. Чтобы вернуть поток Blender, повторно запустите скрипт или вызовите `request_device_status()`.

## Команды в Blender Python Console

```python
print_status()                    # счётчики, возраст данных каждого ID
request_device_status()           # запрос STATUS у ESP32
set_stream_rate(10)               # 1…100 Гц
set_sensor_id_mode("auto")        # auto / sequential / tca_channel
calibrate_neutral_pose()          # повторно захватить N-позу
hardware_calibrate()              # только гироскопы; допустимо на человеке
full_hardware_calibrate()         # accel+gyro; датчики снять и положить Z вверх
stop_udp_mocap()                  # закрыть сокет Blender
stop_udp_mocap(True)              # закрыть сокет и отправить устройству STOP
start_udp_mocap()                 # повторное подключение
```

## Настройка осей

В начале `udp_mocap.py` находится словарь:

```python
AXIS_MAPS = {
    0: ("+X", "+Y", "+Z"),
    1: ("+X", "+Y", "+Z"),
    2: ("+X", "+Y", "+Z"),
    6: ("+X", "+Y", "+Z"),
    7: ("+X", "+Y", "+Z"),
}
```

Тройка описывает, из какой подписанной оси сенсора получить Blender X, Y и Z. Каждая исходная ось должна встречаться ровно один раз.

Примеры:

```python
("+X", "+Y", "+Z")  # без перестановки
("+X", "+Z", "-Y")  # поменять Y/Z, инвертировать новый Z
("-Y", "+X", "+Z")  # перестановка и знак в плоскости XY
```

Оси можно менять без редактирования текста:

```python
set_axis_map(0, "+X", "+Z", "-Y")
```

После изменения автоматически запрашивается новая neutral pose. Если все три оси выглядят инвертированными или движение идёт в противоположной системе отсчёта, сначала попробуйте:

```python
INVERT_ALL_INPUT_QUATERNIONS = True
```

Практический порядок поиска осей:

1. Оставьте четыре сегмента неподвижными.
2. Двигайте только один сегмент в одной плоскости.
3. Проверьте, какая ось Blender реагирует.
4. Переставьте X/Y/Z в `AXIS_MAPS`.
5. Если направление неверно, поменяйте только знак.
6. Снова выполните `calibrate_neutral_pose()`.
7. После плеч отдельно проверьте чистое сгибание каждого локтя.

## Рекомендуемая калибровка

Калибровка здесь состоит из трёх разных задач. Их нельзя заменять одной кнопкой.

### 1. Калибровка измерительных смещений MPU6050

Локальная I2Cdevlib `CalibrateAccel()` целится в показания X=0, Y=0, Z=+1 g. Поэтому полная `CALIB` корректна только когда **каждый снятый модуль лежит неподвижно, локальной осью Z вертикально вверх**.

Рекомендуемый порядок перед сессией:

1. Положите все пять модулей на жёсткую горизонтальную поверхность одинаковой стороной вверх.
2. Включите систему и не трогайте её до `RDY:sensors_ready`: прошивка выполняет полную accel+gyro калибровку при старте.
3. Не перезагружая ESP32, закрепите модули на человеке.
4. Если после закрепления нужно обновить только ноль гироскопов, человек замирает, а в Blender вызывается `hardware_calibrate()`. Эта функция отправляет `CALIB_GYRO` и не портит акселерометрическую калибровку.
5. `full_hardware_calibrate()` на надетых вертикально/боком датчиках не использовать.

### 2. Фиксация датчика на сегменте

- Корпус датчика не должен проворачиваться или скользить относительно сегмента.
- Крепление должно быть повторяемым: отметьте верх, направление разъёма и положение центра каждого модуля.
- Избегайте мягких участков с большой мышечной/жировой деформацией; движение кожи относительно кости создаёт soft-tissue artifact.
- Провода закрепите отдельно, чтобы они не тянули модуль.
- После любой перестановки, ослабления ремня или смены человека neutral pose выполняется заново.

Статическая калибровка проста, но зависит от точности позы и крепления. Исследования верхней конечности показывают, что функциональная калибровка по движениям сустава часто точнее статической. Для метрических углов локтя/плеча следующей доработкой должна быть оценка функциональных осей по серии чистых сгибаний локтя и подъёмов плеча; текущая версия делает устойчивую статическую N-pose калибровку.

### 3. Общая N-поза sensor-to-segment

Перед Run Script или вызовом `calibrate_neutral_pose()`:

1. Стойте прямо, вес распределён равномерно.
2. Спина нейтральна, взгляд вперёд.
3. Руки свободно опущены вдоль корпуса.
4. Локти разогнуты без усилия.
5. Ладони направлены к бёдрам; не вращайте предплечья.
6. Все пять датчиков неподвижны не менее нескольких кадров.
7. Запустите захват neutral pose и дождитесь сообщения `neutral pose captured`.
8. Сделайте контроль: наклон корпуса, подъём каждой руки, отдельное сгибание каждого локтя, возврат в N-позу.

Скрипт ждёт свежий согласованный набор всех пяти ID, а не калибрует каждый датчик в случайный момент. Постоянный монтажный поворот датчика сокращается в относительном повороте `current × neutral⁻¹`.

### Ограничение MPU6050 по курсу

MPU6050 — 6-осевой прибор: акселерометр даёт направление гравитации, но не абсолютный курс вокруг вертикали. Без магнитометра или внешнего/модельного ограничения heading не наблюдаем и медленно дрейфует. N-поза выравнивает начальные курсы, но не устраняет последующий независимый yaw drift пяти гироскопов.

Практически:

- выполняйте N-pose непосредственно перед записью;
- для длинной сессии периодически возвращайтесь в N-позу и вызывайте `calibrate_neutral_pose()`;
- контролируйте возврат локтей и плеч визуально;
- для длительного метрического mocap используйте IMU с магнитометром в магнитно чистой зоне либо алгоритм с кинематическими joint constraints/онлайн sensor-to-segment оцениванием.

## Пересборка .blend

После изменения внешнего `udp_mocap.py` встроите его в проект снова:

```bash
blender --background --python blender/build_udp_blend.py -- \
  blender/Human_spine_N_sensors.blend1 \
  blender/Human_spine_UDP.blend \
  blender/udp_mocap.py
```

## Тестирование

Полная headless-проверка пересобирает проект во временную папку и проверяет
структуру рига, совпадение встроенного скрипта с исходником, разбор UDP-кадров,
атомарный neutral frame, иерархические повороты корпуса/рук и команды устройству:

```bash
./blender/test.sh
```

Для запуска через нестандартный бинарник Blender:

```bash
BLENDER_BIN=/path/to/blender ./blender/test.sh
```

Проверка с включённым реальным контроллером:

```bash
blender --background blender/Human_spine_UDP.blend --python-exit-code 1 \
  --python blender/test_hardware.py -- \
  blender/udp_mocap.py 192.168.1.117 4210 5
```
