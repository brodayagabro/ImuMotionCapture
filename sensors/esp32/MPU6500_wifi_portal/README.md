# MPU6500: сохранение Wi-Fi и веб-настройка

Отдельный вариант **MPU6500_with_TCA9548A_udp** для ESP32-C3/C6.
Главный файл — `MPU6500_wifi_portal.ino`. Исходная прошивка не изменена.
Скопированы её работа с датчиками, команды, калибровка и отдельные
`MahonyFilter.h/.cpp`; изменена только организация Wi-Fi-подключения.
`wifi_secrets.h` не нужен, реквизитов чужой сети в исходниках нет.

## Первый запуск и смена сети

1. Загрузите этот скетч. При отсутствии сохранённых реквизитов сразу
   появляется точка **MOCAP_MIPT**, пароль **12345678**.
2. Подключитесь к ней с телефона или компьютера. Если ОС предупреждает,
   что интернета нет, останьтесь подключёнными к этой сети.
3. Откройте **http://192.168.4.1/** (именно HTTP, не HTTPS).
   Автоматическое открытие captive portal не требуется и не реализовано.
4. Введите SSID и пароль сети **2,4 ГГц**, нажмите **«Сохранить и подключиться»**.
   SSID: 1–32 байта, пароль: 8–63 байта либо 64 hex-символа PSK.
   Для открытой сети пароль пустой. Пробелы не обрезаются.
5. Контроллер проверяет сеть: максимум **три попытки по 20 секунд**.
   Страница обновляется каждые три секунды. Во время подключения точка
   настройки остаётся доступной; при смене радиоканала клиент может временно
   отключиться — подключитесь к MOCAP_MIPT ещё раз.
6. При успехе реквизиты записываются в NVS, страница и Serial (115200 бод)
   показывают IP, выданный роутером. Через 15 секунд точка настройки и HTTP
   отключаются. Вернитесь в основную сеть и укажите IP костюма в приложении,
   порт **4210**, подключитесь и нажмите **START**.

В последующие включения используются последние **успешно подключённые**
SSID/пароль. Если за три попытки подключиться не удалось, открывается та же
точка настройки. При неправильном новом пароле прежние данные в памяти
не заменяются, форма снова доступна после завершения попыток. Чтобы сменить
доступную сеть, временно выключите прежнюю точку или включите костюм вне её
зоны действия. При потере сети во время работы тоже выполняются три попытки,
затем включается режим настройки.

IP в основной сети назначается DHCP и не обязан быть `192.168.1.117`.
`192.168.4.1` — адрес только точки настройки. Порт приложения не меняется.
После потери сети UDP-клиент сбрасывается: приложению нужно подключиться
заново (`HELLO`, затем `START`). При загрузке автоматического START нет.

## Память и безопасность

В ESP32 вместо отдельной EEPROM используется **NVS / Preferences**:
[документация Espressif](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/preferences.html).
Wi-Fi хранится одним blob `credentials` в пространстве `mocap_wifi`:
SSID и пароль записываются вместе, результат записи проверяется.
Калибровка датчиков по-прежнему хранится отдельно в `mpu6500_cal` и не стирается.
Запись производится при успешной настройке через форму, не в каждом цикле
и не при обычном переподключении. Полное стирание flash удаляет настройки.

Конфигурационная страница доступна только через интерфейс точки настройки,
не через интерфейс основной сети. Пароль не возвращается в HTML и не
выводится в Serial; форма использует POST и случайный токен сессии.
Но HTTP и стандартный NVS здесь не зашифрованы на уровне приложения.
Любой знающий общий пароль `12345678` рядом с устройством может войти в
режим настройки, пока точка активна. Настраивайте устройство в доверенном
окружении; AP не предназначена для постоянной работы.

## Сборка

Нужен ESP32 Arduino core; дополнительные сторонние библиотеки не требуются.
Откройте `MPU6500_wifi_portal.ino` в Arduino IDE, выберите свою плату.
Все файлы этой папки должны оставаться рядом:

- `.ino` — датчики, Serial и прежний UDP-протокол;
- `WiFiPortal.h/.cpp` — NVS, Wi-Fi STA/AP и веб-страница;
- `WiFiRetry.h` — неблокирующий бюджет трёх попыток;
- `MahonyFilter.h/.cpp` — неизменённый фильтр исходного варианта.

Пример для CLI из корня репозитория:

```bash
arduino-cli compile --fqbn esp32:esp32:esp32c3 sensors/esp32/MPU6500_wifi_portal
# Для C6:
arduino-cli compile --fqbn esp32:esp32:esp32c6 sensors/esp32/MPU6500_wifi_portal
g++ -std=c++17 -Wall -Wextra -Werror tools/benchmarks/mpu_gravity/test_wifi_retry.cpp -o /tmp/test_wifi_retry
/tmp/test_wifi_retry
```

Ожидание Wi-Fi организовано через `millis()`, без блокирующего 20-секундного
цикла: основной loop продолжает обслуживать фильтры и Serial.
Оригинальные команды `HELLO`, `PING`, `START`, `STOP`, `STATUS`, `GET_CONFIG`,
`SET_RATE`, `CALIB`, `CALIB_GYRO` и строки `FRAME/Q` сохранены.

## Проверка на устройстве

После сборки проверьте на реальной плате: первый запуск без реквизитов,
правильный пароль и повторное включение, недоступную сеть (AP через примерно
60 секунд после начала Wi-Fi-подключения), неправильный новый пароль
(форма остаётся, старая запись сохраняется), возврат сети и приём `FRAME/Q`.
Для измерения задержки не включайте время первоначальной инициализации IMU.
Проверьте также открытый SSID, сохранность IMU-калибровки и отказ записи NVS.
