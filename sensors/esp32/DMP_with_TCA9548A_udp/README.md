# MPU6050 ×5 через TCA9548A: UDP motion capture

Проект принимает кватернионы пяти MPU6050 от ESP32 по UDP и визуализирует
движение человека. Основное настольное приложение написано на PyQt6.

## Состав проекта

- mpu_udp_viewer.py — совместимый launcher основного PyQt6-приложения;
- pyqt_mocap/ — отдельный самодостаточный пакет приложения и его README;
- mocap_core.py — UDP-протокол, кватернионы, N-поза и кинематическая модель;
- mpu_udp_viewer_tk.py — сохранённая предыдущая версия с кубами;
- DMP_with_TCA9548A_10HZ_upd.ino — прошивка ESP32-C3/C6;
- blender/ — исходный Blender-проект;
- test_frequency/ — измерение и анализ частоты UDP-пакетов;
- tests/test_mocap_core.py — headless-тесты нового приложения.

## Установка и запуск

Для проекта используется окружение ./.env:

    python3 -m venv .env
    source .env/bin/activate
    python -m pip install -r requirements.txt
    python mpu_udp_viewer.py
    python -m pyqt_mocap

Все зависимости, включая matplotlib из test_frequency/pyproject.toml,
объединены в корневом requirements.txt:

- PyQt6 — интерфейс;
- matplotlib — интерактивная 3D-сцена и графики анализа частоты;
- numpy — кватернионы и кинематика.
- pandas — анализ результатов из test_frequency.

На Linux для Qt нужен работающий X11 или Wayland display. На Ubuntu 24.04
для платформенного плагина xcb также установите системную библиотеку:

    sudo apt-get install libxcb-cursor0

## Интерфейс приложения

В верхней части главного окна находятся кнопки:

- Подключиться / Отключиться — открыть или закрыть UDP-сокет;
- START — задать выбранную частоту, запустить поток и запросить N-позу;
- STOP — остановить поток на ESP32;
- КАЛИБРОВКА — N-поза, комплексная N/T/forward или аппаратная калибровка;
- Настройки — открыть отдельное окно параметров.

Справа расположен монитор полных входящих и исходящих UDP-пакетов и поле
произвольной ASCII-команды. 3D-сцену можно вращать и масштабировать мышью.

Окно настроек открывается через Правка → Настройки (Ctrl+,) и содержит:

1. Сеть — IP/имя ESP32 и UDP-порт. При изменении открытое соединение
   автоматически пересоздаётся; активный поток запускается снова.
2. Датчики — формат входных ID и соответствие ID сегментам тела.
3. Оси — signed permutation осей для каждого сегмента, совместимая с
   AXIS_MAPS Blender-драйвера.
4. Частота кадров — поток ESP32 1…100 кадр/с и отдельная перерисовка
   интерфейса 5…60 FPS.

Изменение частоты ESP32 при открытом соединении сразу отправляет:

    SET_RATE <1..100>

Перезапуск приложения не нужен. Параметры сохраняются через QSettings.

## Модель человека и датчики

Перенесены те же пять имён сегментов, что используются ригом Blender:

| Канонический ID | Имя сегмента | Родитель |
|---:|---|---|
| 2 | spine | корневой сегмент |
| 7 | shoulder.L | spine |
| 6 | forearm.L | shoulder.L |
| 0 | shoulder.R | spine |
| 1 | forearm.R | shoulder.R |

Назначения можно изменить во вкладке Датчики. По умолчанию auto распознаёт:

В той же таблице флажок «Смотреть» включает датчик в обработку. По умолчанию
`spine`/канал 2 выключен: корпус остаётся неподвижным, его кватернионы
игнорируются, а четыре датчика рук включены.

- физические TCA-каналы 0, 1, 2, 6, 7;
- последовательные ID 1, 2, 3, 4, 5, автоматически переводимые в
  канонические 0, 1, 2, 6, 7.

Для нестандартной нумерации выберите Без преобразования ID.

На каждом отслеживаемом сегменте нарисованы локальные направляющие:

- X — красная;
- Y — зелёная;
- Z — синяя.

Рядом показаны имя Blender-сегмента и назначенный датчик, например
forearm.L [S6]. Ноги, голова и соединения дорисовываются как кинематическое
приближение; датчики управляют корпусом и руками.

Начиная с ревизии схемы 2 группы датчиков рук поменяны местами: каналы 7/6
управляют левой рукой, а 0/1 — правой. Сохранённая прежняя штатная схема
обновляется автоматически; нестандартное ручное назначение ID не меняется.

Монтажные оси по умолчанию: слева `+X +Y +Z`, справа `-X -Y +Z`,
на корпусе `+X -Z +Y`. Это соответствует описанным направлениям в позе
«руки вперёд»: Z рук вверх; Y слева к пальцам, Y справа к локтю; у корпуса
X вправо, Y вверх, Z назад.

Подробная документация отдельного приложения находится в
`pyqt_mocap/README.md`.

## N-поза и калибровка

Приложение использует алгоритм Blender-проекта:

1. N-поза использует один свежий UDP-кадр со всеми включёнными датчиками;
   отключённые сегменты фиксируются в нейтральной ориентации.
2. Signed permutation приводит оси каждого датчика к начальному описанию
   монтажа на сегменте тела.
3. Комплексная калибровка по переходам N → T и N → «руки вперёд» дополнительно
   вычисляет непрерывную sensor-to-segment поправку осей для каждого датчика рук.
4. Для каждого сегмента вычисляется поворот относительно согласованной N-позы;
   плечи соединяются с повернутым корпусом, предплечья — с локтями.
5. Между кадрами применяется quaternion slerp.

Перед START стойте прямо, держите руки вниз, локти разогнутыми, ладони
направьте к бёдрам и не двигайтесь до сообщения об успешном захвате N-позы.

Кнопка КАЛИБРОВКА предлагает:

- Только N-поза — безопасная программная перекалибровка;
- Гироскоп + N-поза — CALIB_GYRO для надетых неподвижных датчиков;
- Полная MPU6050 — CALIB только для снятых модулей, лежащих одинаковой
  стороной и локальной Z вверх. На человеке этот режим использовать нельзя.
- Комплексная N → T → вперёд — автоматическая настройка осей и дрейфа.

Для комплексной калибровки поток должен быть активен. Мастер последовательно
записывает N-позу, T-позу и руки вперёд — каждую по 5 секунд. Он усредняет
только новые UDP-кадры, проверяет направления, согласует дискретные и
непрерывные оси датчиков рук и оценивает стационарный дрейф. Предупреждение о
высокой ошибке теперь появляется при остаточной ошибке выше 45°.
Результат можно экспортировать в JSON и позже импортировать через меню
«Файл». После импорта требуется свежая N-поза, поскольку мировая система DMP
может измениться после перезапуска контроллера.

Повторная команда «Только N-поза» сохраняет уже найденное согласование осей и
обновляет лишь нейтральный отсчёт. Одна N-поза без T-позы не позволяет
однозначно определить все три оси, поэтому первичное согласование выполняется
комплексным мастером.

После перестановки датчика, изменения маппинга или осей N-позу нужно повторить.

MPU6050 не имеет магнитометра: абсолютный курс вокруг вертикали не наблюдаем и
со временем дрейфует. Для длинной записи периодически повторяйте N-позу.

## Настройка и прошивка ESP32

Перед прошивкой задайте сеть и порт в начале скетча:

    static const char *WIFI_SSID = "...";
    static const char *WIFI_PASSWORD = "...";
    static const uint16_t UDP_LISTEN_PORT = 4210U;

Для сборки нужны ESP32 Arduino core (WiFi, AsyncUDP) и I2devlib
(I2Cdev, MPU6050_6Axis_MotionApps20). Serial Monitor работает на 115200 бод.

ESP32 хранит только одного получателя. Последняя команда от PyQt, Blender,
test_frequency.py или nc переключает поток на сокет отправителя.

## UDP-протокол

Поддерживаемые ASCII-команды:

    HELLO
    PING
    START
    STOP
    STATUS
    GET_CONFIG
    CALIB
    CALIB_GYRO
    SET_RATE <1..100>

Один кадр передаётся одной UDP-датаграммой:

    FRAME <sequence> <millis> <quaternion_count>
    Q <sensor_id> <w> <x> <y> <z>
    Q <sensor_id> <w> <x> <y> <z>

Кватернион использует порядок w x y z. UDP не гарантирует доставку: редкая
потеря допустима, следующий пакет содержит актуальное состояние.

## Проверки

Тесты нового приложения:

    source .env/bin/activate
    python -m py_compile mocap_core.py mpu_udp_viewer.py
    python -m unittest discover -s tests -v
    QT_QPA_PLATFORM=offscreen python -m unittest discover -s pyqt_mocap/tests -v

Они проверяют signed axis maps, оба профиля ID, атомарный захват N-позы,
изолированное движение конечности и локальные оси всех пяти сегментов.

Blender-проект проверяется отдельно:

    ./blender/test.sh

## Измерение частоты UDP

Дополнительная установка в test_frequency больше не нужна:

    source .env/bin/activate
    python test_frequency/test_frequency.py 192.168.1.117
    python test_frequency/analyze_frequency.py

Точные аргументы доступны через --help. Скрипт измерения временно становится
единственным получателем потока ESP32.

## Диагностика сети

Если пакеты не приходят:

- проверьте IP и порт в Правка → Настройки;
- убедитесь, что компьютер и ESP32 находятся в одной сети;
- отключите изоляцию клиентов гостевой Wi-Fi;
- разрешите входящие UDP-ответы в firewall;
- отправьте PING или STATUS через поле произвольной команды;
- проверьте в мониторе ACK и определившийся профиль ID.

Без GUI команды можно отправлять утилитой:

    nc -u 192.168.1.X 4210

Подробности Blender-рига и sensor-to-segment калибровки находятся в
blender/README.md.
