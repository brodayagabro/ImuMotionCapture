# Semaphore Experiment Presenter

Отдельное приложение для предъявления семафорных слов. Оно показывает позы,
управляет последовательностью и отправляет метки в универсальный рекордер.
Рекордер и демонстратор запускаются **двумя процессами** на одном компьютере.
Демонстратор не подключается к костюмам и не оценивает движения участника.

## Запуск

Из корня репозитория, в существующем окружении Python 3.11+ с PyQt6:

```powershell
.venv\Scripts\python.exe scripts\noitom_comparison\main.py --event-port 5055
```

Подключите оба потока и включите **REC · эксперимент**. Затем во втором терминале:

```powershell
.venv\Scripts\python.exe -m scripts.experiments.semaphore.main --participant P001
```

1. Во вкладке **Проверка поз** проверьте все 28 букв, подписи рук и отражение.
   Кнопки «Предыдущая» и «Следующая» работают только до/после сессии.
2. Нажмите **Подключить рекордер**. Готовность `CONNECTED · READY · REC`
   означает успешный handshake и активную запись. Доступность данных обоих
   костюмов отдельно проверяется в окне рекордера; handshake этого не проверяет.
3. Задайте код участника (например, `P001`, без ФИО), порядок блоков и при
   необходимости seed. Пустое поле seed создаёт и сохраняет случайное значение.
4. Выберите экран. **Окно участника** открывает отдельное окно;
   **Полный экран · F11** разворачивает его на выбранном мониторе.
   В окне участника F11 переключает полноэкранный режим, Esc выходит из него.
5. При необходимости нажмите **Тренировка**, затем **Начать блок**.
   Четыре тренировочных слова образуют отдельную сессию с отдельным счётчиком.
6. **Начать эксперимент** создаёт сессию и показывает название первого блока.
   Нажмите **Начать блок**, когда участник готов. Слова внутри блока идут
   автоматически. Между блоками — отдых без ограничения времени;
   **Начать следующий блок** запускает второй блок.
7. Дождитесь завершения и нулевого числа ожидающих подтверждений, затем
   остановите REC в рекордере. Закрытие демонстратора также ожидает последние
   ACK, не блокируя интерфейс; при потере подтверждений сессия помечается неполной.

**Пауза / Продолжить** сохраняют текущую фазу, позу и оставшееся время.
**Повторить пробу** завершает текущую попытку с `outcome=repeated` и начинает
то же слово с подготовки, увеличивая `attempt`. **Пропустить пробу** записывает
`outcome=skipped` и переходит к следующему слову. **Завершить** записывает
`outcome=stopped`. Плановые номера проб не меняются при повторе.

При потере TCP, ACK или REC эксперимент автоматически приостанавливается.
После подключения нужно повторить текущую пробу (либо явно пропустить её).
Автоматической переотправки старых меток нет: их получение в другое время
создало бы неверные временные метки. Если связь потеряна между пробами, можно
продолжить межпробный интервал. Закрытие окна участника во время пробы тоже
требует её повтора. Потеря связи проверяется heartbeat раз в секунду и таймаутом
ответа/ACK 3 секунды; обнаружение обрыва TCP обычно происходит раньше.

## Конфигурация

`configs/experiment.json` ссылается на `lower_words.json` и `upper_words.json`
относительно собственного каталога. В каждом блоке 20 слов, по 3 повтора:
**60 + 60 = 120 проб**. Каждый повтор содержит каждое слово ровно один раз.
Случайная перестановка воспроизводится по seed; одинаковые слова на стыке
повторов разводятся, когда слов больше одного. Порядок блоков выбирает оператор.

| Фаза | По умолчанию |
| --- | ---: |
| Подготовка в нейтральной позе | 2,0 с |
| Показ целого слова | 1,0 с |
| Переход к каждой букве | 0,4 с |
| Удержание каждой буквы | 0,8 с |
| Возврат в нейтральную позу | 0,4 с |
| Нейтральная поза после слова | 1,5 с |
| Интервал между словами | 1,5 с |

Таймер работает по `time.monotonic_ns()`, QTimer только обновляет интерфейс.
При опоздании GUI следующая фаза получает полную длительность с момента
фактического перехода. Опоздание более 100 мс записывается как `scheduler_delay`.
Невидимые фазы не пропускаются. Полоса прогресса включает переход и удержание.

Все слова проверяются до запуска: неизвестная буква, смешение наборов,
дубликаты слов в основном блоке или некорректные длительности запрещают старт.
Нейтральная поза задана отдельно и не считается буквой.

Дополнительные параметры:

```powershell
.venv\Scripts\python.exe -m scripts.experiments.semaphore.main --config scripts\experiments\semaphore\configs\experiment.json --participant P003 --seed 18372 --recorder-host 127.0.0.1 --recorder-port 5055
```

Только для отладки:

```powershell
.venv\Scripts\python.exe -m scripts.experiments.semaphore.main --debug --debug-speed 5
```

`--debug` показывает углы и частоту обновления у оператора. Запуск без рекордера
нужно **явно** включить отдельной галочкой. Такая сессия сохраняется с
`offline=true`. `--debug-speed` делит длительности на заданный коэффициент;
фактические длительности попадают в копию протокола. На экран участника
отладочные показатели не выводятся.

## Руки, углы и отражение

Таблица в `semaphore_model.py` перенесена из рисунка 156 «Русская семафорная
азбука» в [«Справочнике сигнальщика» Н. С. Серебряного и Б. Б. Жданова](https://flot.com/publications/books/shelf/signalman/83.htm).
Используются 28 букв из ТЗ; Е и Э в источнике имеют одну позу. Это схема
направлений прямых рук без флагов и отдельных углов локтей, а не анатомическая
модель. В позах с пересечением тела руки могут перекрываться на рисунке.

Повторная сверка всех 28 используемых букв выявила и исправила в версии 0.1.1
перестановку анатомических рук в «Х» и «Ю». У «Х» **правая рука вверх-вправо,
левая вниз-вправо** (левая 315°, правая 45°); у «Ю» **правая вверх-вправо,
левая горизонтально вправо** (левая 0°, правая 45°). Направления указаны
со стороны участника. Остальные 26 поз подтверждены по той же таблице.
Тесты дополнительно проверяют симметричные пары Б–Д, В–Г, Ж–З, К–Х, Л–М,
Н–О, П–Р, Ф–Ы, Ц–Ч, Ш–Щ, Ю–Я и положение рук в обоих режимах отражения.
Для применения исправления перезапустите демонстратор. В старых записях
сохраняется исходная таблица в `protocol.json`; новые записи содержат
исправленные углы и версию 0.1.1 в `metadata.json`.

Левая и правая руки — анатомические стороны **участника**. Углы определены
в его плоскости: 0° вправо, 90° вверх, 180° влево, 270° вниз. Плечо левой
руки имеет отрицательную горизонтальную координату до отражения.

Семантика `mirror_mode` следует ТЗ буквально:

- `true`: левое плечо/левая рука участника расположены справа на изображении;
- `false`: слева на изображении.

Отражается вся геометрия по горизонтали, идентификаторы рук и углы не меняются.
Переключатель в браузере поз служит только для ручной проверки и **не меняет
конфигурацию эксперимента**. Для исследования выберите одно значение в JSON
и сохраняйте его между участниками. Интерполяция идёт по кратчайшей дуге с
smoothstep; при разнице ровно 180° выбрано убывание угла.

Перед записью участников проверьте таблицу в браузере поз и выполните тренировку.
Программные проверки углов и отражения не заменяют методическую проверку того,
как участник понимает инструкцию о сторонах рук.

## События и синхронизация

Связь — TCP, только loopback, по умолчанию `127.0.0.1:5055`.
UTF-8 JSON, один объект на строку, ограничение 64 КиБ. `TCP_NODELAY` включён.
В рекордере приём реализован отдельным сервером, без Qt и без знаний о семафоре.
Описание универсального протокола находится в
[README рекордера](../../noitom_comparison/README.md#внешние-события).

Каждое событие имеет уникальный `event_id`, ID сессии демонстратора `session_id`,
ID участника, seed, SHA-256 копии протокола и целевую `recording_session_id`.
В событиях пробы также есть `trial_id`, `block`, `word`, `repeat`, `attempt`,
`letter`, `letter_index`. Индексы букв начинаются с **0**; номера проб,
повторов и попыток — с **1**. В тренировке **каждое** событие содержит
`training_trial=true`.

События: `experiment_start/pause/resume/end`, `block_start/end`,
`trial_prepare/start/end`, `word_show`, `letter_transition_start`,
`letter_hold_start/end`, `neutral_transition_start`, `neutral_hold_start`.
У `trial_end` есть `outcome`. У `letter_hold_end` есть `completed`, чтобы
отличить полное удержание от прерванной попытки. Интервалы паузы следует
исключать при анализе удержаний.

Основная временная метка — **`host_timestamp_ns` рекордера в момент получения
целого сообщения**. Используется тот же monotonic clock, что при приёме MoCap.
`local_monotonic_ns` демонстратора служит только для диагностики. Синхронизации
по FPS, номерам кадров или сетевому round-trip нет. ACK всех событий приходит
асинхронно и не управляет скоростью анимации.

Метка соответствует получению команды рекордером, а не измеренному моменту
свечения пикселя на мониторе: задержки Qt, ОС, сети и дисплея остаются.
Для оценки этой задержки можно сопоставить диагностическое время отправителя
и ACK; для точного физического onset потребовалось бы отдельное измерение.

## Файлы сессии

По умолчанию `records/semaphore/<participant>_<date>_<time>_<suffix>/`.
Относительный `sessions_dir` отсчитывается от корня репозитория. Каталог
`records/` уже исключён из Git.

| Файл | Содержимое |
| --- | --- |
| `metadata.json` | Участник и снимок его карточки, ID, seed, порядок блоков/слов, времена, версия, начало/окончание, итог, offline, проблемы доставки, число ACK, ID и пути связанных записей |
| `protocol.json` | Фактическая конфигурация со словами, таблицей углов, источником и семантикой отражения |
| `trial_order.csv` | План проб, включая номер слова внутри повтора и признак тренировки |
| `presenter_events.csv` | Локальное диагностическое время и полный JSON каждого события |
| `recorder_acks.csv` | `event_id`, подтверждённая метка рекордера, ID и фактическая папка записи |

Основные данные движений и `events.csv` остаются в каталоге сессии рекордера.
В его `details_json` сохраняется исходное сообщение целиком, а
`relative_timestamp_ns = host_timestamp_ns − recording_t0_ns`.
Успешный ACK означает принятие события в очередь записи, а не принудительный
сброс диска. После завершения нужно учитывать итоговый статус **обоих** приложений.
В одной записи рекордера могут находиться отдельные тренировочная и основная
сессии демонстратора; их различают по `session_id` и `training_trial`.

Проблемы доставки сохраняются и оставляют общий статус `incomplete`, даже если
потерянная проба затем повторена. Для анализа выбирайте полные попытки по
`trial_id + attempt`, проверяя наличие пар начала/конца и соответствующих ACK.

## Реестр датасета и сопоставление записей

Начиная с 0.2.0, общие таблицы находятся в **`records/semaphore/dataset/`**.
Вкладка **Датасет** показывает связи и обновляет CSV в фоне. Реестр автоматически
пересобирается после завершения сессии и подтверждения последних меток.
После **STOP REC** нажмите **Обновить реестр**, чтобы получить окончательные
статусы и число кадров рекордера. Во время записи эти поля могут быть неполными.
Кнопка **Папка таблиц** открывает каталог результатов.

Карточка участника содержит **код, ведущую руку и примечание**. Она сохраняется
кнопкой **Сохранить карточку участника**, а также при начале сессии, в
`records/semaphore/participants/<код>.json`. При вводе ранее использованного
кода поля заполняются из карточки. В `metadata.json` каждой новой сессии
сохраняется отдельная копия карточки. Последующее изменение карточки не меняет
историю сессии. Неизвестная ведущая рука остаётся пустой; значения `right`,
`left`, `ambidextrous` означают правую, левую и обе руки.

| Таблица | Одна строка | Назначение |
| --- | --- | --- |
| `participants.csv` | Участник | Текущие сведения, число сессий, даты первого/последнего запуска |
| **`dataset_index.csv`** | Сессия демонстратора × запись костюмов | Основной реестр: участник, даты, параметры эксперимента, обе папки, файлы, статусы и счётчики |
| `trial_attempts.csv` | Попытка слова в одной записи | Слово, блок, повтор, номер попытки, границы и исход: completed/repeated/skipped/stopped |
| `letter_holds.csv` | Удержание буквы в одной попытке | Буква и её позиция в слове, временной интервал рекордера и пути к обоим потокам |
| `unlinked_recordings.csv` | Запись костюмов без связи с найденными сессиями | Старые/самостоятельные записи, которым нельзя автоматически приписать участника |

`report.json` содержит время сборки, количество строк и замечания к исходным
файлам. CSV — UTF-8 с BOM, разделитель запятая. Это производные таблицы: при
обновлении они пересоздаются из исходных журналов, править их вручную не нужно.
Исходные записи не перемещаются и не изменяются. Каталог `records/` исключён
из Git, включая карточки и реестр.

**Ключи связи:**

```text
participant_id
  └─ session_id (запуск демонстратора: тренировка или эксперимент)
       └─ recording_session_id (запись костюмов)
            └─ trial_id + attempt (попытка слова)
                 └─ letter_index (позиция буквы, начиная с 0)
```

Одна запись REC может содержать тренировку и основной эксперимент. Один запуск
может ссылаться на несколько REC после восстановления связи. Поэтому число
строк `dataset_index.csv` не всегда равно числу экспериментов; уникальный
запуск определяется по `session_id`. Число кадров относится ко **всей записи
REC** и повторяется в связанных строках: суммировать его по строкам нельзя.

Сопоставление использует ID из `events.csv`, локальных событий и ACK. Совпадение
дат или похожие имена папок не используется. Для старых записей без пути в ACK
проверяется `recordings/`; для новых рекордер сообщает свой фактический путь.
Статусы связи:

- `events_verified`: события с согласованными ID найдены в записи рекордера;
- `ack_only`: ACK есть, но события ещё не найдены на диске;
- `unconfirmed`: есть только намерение отправить события в эту запись;
- `missing_recording`: ID известен, папка не найдена;
- `ambiguous_recording`: в указанных каталогах несколько копий с одним ID;
- `offline`: намеренный запуск без рекордера; `unmatched`: связь неизвестна.

`events_verified` подтверждает связь, а не полноту движений или точность
калибровки. Поля `presenter_status` и `recording_status` независимы. Дополнительно
смотрите `missing_recorded_events`, `delivery_issue_count`, число кадров,
наличие файлов, `synthetic_noitom` и `recorder_incomplete_reasons`.
Пустой счётчик значит «пока неизвестно», а `0` — известное отсутствие кадров.

Основные колонки реестра:

| Группа | Колонки |
| --- | --- |
| Респондент | `participant_id`, `handedness`, `participant_notes`, `participant_profile_source` |
| Даты | `started_at`, `ended_at`, `recording_started_at` — ISO 8601 с часовым поясом |
| Сессия | `session_id`, `training_trial`, `presenter_status`, `offline` |
| Запись | `recording_session_id`, `link_status`, `recording_status` |
| Пути | `presenter_dir`, `recording_dir`, `presenter_metadata_file`, `recorder_metadata_file`, `protocol_file`, `events_file`, `own_frames_file`, `noitom_frames_file` |
| Протокол | `application_version`, `protocol_sha256`, `random_seed`, `block_order`, `repetitions`, `mirror_mode`, длительности `*_s` |
| Полнота | План/факт проб, метки и ACK, число кадров, наличие файлов и причины incomplete |

В старых сессиях ведущая рука и примечание не собирались: эти поля остаются
пустыми с `participant_profile_source=not_collected`. Текущую карточку можно
присоединить отдельно из `participants.csv` по `participant_id`. Дата окончания
старых сессий тоже может отсутствовать; она не вычисляется из даты файла.

Пути в CSV отсчитываются **от папки с CSV**, чтобы каталоги можно было переносить
вместе, сохраняя их взаимное расположение. Для разных дисков Windows путь может
быть абсолютным. После переноса или добавления папок реестр можно пересоздать:

```powershell
.venv\Scripts\python.exe -m scripts.experiments.semaphore.dataset
```

Для другого расположения записей (параметр `--recordings-root` можно повторять):

```powershell
.venv\Scripts\python.exe -m scripts.experiments.semaphore.dataset --presenter-root D:\Dataset\records\semaphore --recordings-root D:\Dataset\recordings
```

Явно заданные каталоги имеют приоритет над прежними путями в ACK. Дублирующиеся
ID внутри этих каталогов помечаются неоднозначными, а не выбираются случайно.

## Как выделять движения букв

Границы в `letter_holds.csv` берутся только из **времени приёма рекордера**:
`start_ns` для `letter_hold_start`, `end_ns` для `letter_hold_end`.
Из каждого файла движений выбираются кадры с
`start_ns <= host_timestamp_ns < end_ns`. Так обе системы относятся к одному
предъявлению. Номера кадров двух систем и календарное время для этого не нужны.

Для обычного непрерывного удержания проверьте `boundaries_complete=True`,
`hold_completed=True`, `has_pause=False`, `trial_outcome=completed`, затем
отдельно оцените статус записи и наличие обоих потоков. Это проверка структуры
журнала, а не автоматическая оценка качества движения. Прерванные/пропущенные
попытки сохраняются в таблицах. Интервал, пересекающий паузу, помечается
`has_pause=True`; для его использования нужно разделить его по событиям паузы.
Границы из разных `recording_session_id` никогда не соединяются в один интервал.

Пример чтения одного полного удержания без дополнительных библиотек:

```python
import csv
import json
from pathlib import Path

catalog = Path("records/semaphore/dataset").resolve()
with (catalog / "letter_holds.csv").open(encoding="utf-8-sig", newline="") as f:
    holds = list(csv.DictReader(f))
hold = next(h for h in holds if h["boundaries_complete"] == "True"
            and h["hold_completed"] == "True" and h["has_pause"] == "False"
            and h["trial_outcome"] == "completed")
start, end = int(hold["start_ns"]), int(hold["end_ns"])

def frames_in_interval(path):
    with path.open(encoding="utf-8") as f:
        for line in f:
            frame = json.loads(line)
            if start <= frame["host_timestamp_ns"] < end:
                yield frame

own = list(frames_in_interval(catalog / hold["own_frames_file"]))
noitom = list(frames_in_interval(catalog / hold["noitom_frames_file"]))
print(hold["participant_id"], hold["word"], hold["letter"], len(own), len(noitom))
```

Для пакетной обработки сгруппируйте интервалы по `recording_session_id` и читайте
каждый большой JSONL один раз. Временные метки наносекунд храните как `int64`
или строки: преобразование в float либо пересохранение через Excel может
потерять младшие разряды. При использовании pandas задавайте `dtype` для
`start_ns`, `end_ns`, `duration_ns` явно; пустые границы допустимы.
