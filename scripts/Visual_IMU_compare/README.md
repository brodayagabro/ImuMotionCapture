# Visual / IMU compare: запись камер и синхронизация

Камеры записывают **видео со звуком локально**, затем сервер получает файлы и
синхронизирует их штатным **SkellySync по общему звуку**. На одноплатниках нужны
только системный Python и FFmpeg. Обучения моделей, инференса, SkellyCam и GPU
в этой системе нет. Дальнейшая калибровка и захват движения выполняются отдельно
в официальном FreeMoCap, куда передаётся папка `synchronized_videos`.

```text
USB-камера + микрофон → camera/camera_streamer.py → локальный MKV
                              ↑ команды HTTP         ↓ после остановки
                         server/visual_mocap_server.py
                              ↓ SkellySync (audio)
                         synchronized_videos/*.mp4 → официальный FreeMoCap
```

Два основных Python-файла содержат всё приложение; HTML встроен в сервер.
Названия файлов сохранены для структуры проекта, но `camera_streamer.py`
**больше не отправляет RTSP**. MediaMTX и порт 8554 не нужны.

## Быстрый запуск

На каждом компьютере клонируйте этот репозиторий. Дополнительные репозитории
в `MotionCapture/equipment` не нужны. Команды ниже выполняются из
`scripts/Visual_IMU_compare`.

**Камера 1 (`192.168.1.98`):**

```bash
cd camera
./setup.sh --system-deps --clean-legacy
source .venv/bin/activate
python camera_streamer.py --list-devices
python camera_streamer.py --device /dev/video0 --list-formats
python camera_streamer.py --list-audio
python camera_streamer.py --name cam1 --device /dev/video0 \
  --audio plughw:CARD=Camera,DEV=0 --resolution max --port 8081
```

`plughw:CARD=Camera,DEV=0` — пример, замените результатом `--list-audio`.
На второй камере (`192.168.1.112`) укажите `--name cam2`. Для камеры лучше
использовать постоянный путь `/dev/v4l/by-id/...-video-index0`.
По умолчанию выбирается максимальное разрешение MJPEG/H.264, а затем максимальный
доступный FPS на этом разрешении. `--fps 30` ограничивает выбор режимами 30 FPS;
это может уменьшить выбранное разрешение. Принудительно: `--resolution 1920x1080 --fps 30`.

**Сервер (`192.168.1.90`):**

```bash
cd server
./setup.sh --system-deps --clean-legacy
source .venv/bin/activate
python visual_mocap_server.py \
  --camera cam1=http://192.168.1.98:8081 \
  --camera cam2=http://192.168.1.112:8081 \
  --records "$HOME/mocap-recordings" --port 8080
```

Откройте **http://192.168.1.90:8080**. Видеокарта для синхронизации не нужна.
На сервере нужен Python **3.10–3.12**, на камере — **3.10 и новее** (включая 3.14).
Выбор интерпретатора: `./setup.sh --python /usr/bin/python3.12`.
Установщики не скачивают собственный Python, uv, модели или Blender.

`sudo` используется только с явным `--system-deps` для установки системных
пакетов. Если они уже установлены, запустите `./setup.sh --clean-legacy`.
Подробности: [камера](camera/README.md), [сервер](server/README.md).

## Работа в веб-интерфейсе

1. Проверьте кадр каждой камеры по превью. Оно ограничено 320 px и одним кадром
   в секунду; выключается флажком и при скрытой вкладке. Полное видео по сети
   во время записи не передаётся.
2. Введите имя и выберите `calibration` (калибровочная доска) либо `record`
   (движение). Нажмите «Начать запись на всех камерах».
3. Дождитесь «Все камеры записывают», сделайте общий хлопок или произнесите
   несколько слов, слышимых всем микрофонам. Затем выполните эксперимент.
4. Нажмите «Остановить запись». По умолчанию сервер дождётся завершения файлов,
   выгрузит их с проверкой SHA-256 и запустит SkellySync. Можно снять флажок
   автоматической выгрузки и позже нажать «Выгрузить / повторить».
5. После завершения скопируйте показанный путь `synchronized_videos` и используйте
   его в официальном FreeMoCap / вашем скрипте команд. Путь относится к диску
   сервера, а не браузерному компьютеру.

Повторная запись `calibration` требует подтверждения в интерфейсе.
Прежний набор остаётся текущим до успешной синхронизации нового; его файлы
сохраняются. Здесь «калибровка» означает **набор видео**, а не рассчитанные
параметры камер. Для `record` сохраняется ссылка на текущий набор, если он есть.

## Синхронизация и хранение

Используется [официальный SkellySync](https://docs.freemocap.org/skellysync/),
пакет `skelly_synchronize`, фиксированный commit
`0231c41a3bcb967e231163943a39dd40b50278f1`.
Это другой пакет, чем SkellyCam. Вычисление задержек, выравнивание FPS,
обрезка общего интервала и проверка одинакового количества кадров выполняются
его штатным audio pipeline. Отчёт содержит сдвиги и диагностические графики.
Тишина считается ошибкой; при слабом общем звуке результат нужно проверить по
графикам и видео. Периодический однотонный сигнал для такой проверки не подходит.

Это синхронизация **готовых записей**, не аппаратная синхронизация экспозиции.
Запуск команд по сети не обещает одновременный первый кадр. Разные задержки
микрофонов/камер и дрейф часов на длинных записях могут ограничить точность;
SkellySync определяет постоянный временной сдвиг. Сделайте пробную запись с
видимым хлопком в начале и конце, прежде чем записывать эксперимент.

На камере видео сохраняется в исходном сжатом формате MJPEG/H.264 без
перекодирования, звук — PCM mono. MJPEG высокого разрешения может занимать много
места: проверяйте фактический размер минутного ролика. По умолчанию файлы лежат
в `camera/runtime/recordings/<id>/`; `--records /path` меняет место хранения.
Сервер хранит исходники и синхронизированный результат в
`<records>/takes/<id>/`. Имя и тип находятся в `take.json`, исходники именуются
`<имя>.id-cam1.idx-0.mkv` и т. д. ID предотвращает конфликт одинаковых имён.

Исходники **не удаляются автоматически** после выгрузки. При сетевом сбое
«Выгрузить / повторить» продолжает частично скачанные файлы. После проверки
результата старые записи можно удалить вручную. Синхронизация требует свободного
места под исходники, выходные видео и временные аудиофайлы.

## Переход со старой версии

Остановите старые процессы и службы камер/сервера, затем выполните установку
выше. Старые ключи `--server`, `--device cuda`, `--workflow recording`, RTSP-адреса
и SkellyCam API не используются. Старая служба камеры должна запускать новую
команду: [пример systemd](camera/README.md#автозапуск-systemd).

`--clean-legacy` удаляет только перечисленные в установщике прежние окружения,
чистые загруженные репозитории и кэши этой роли внутри эксперимента. Изменённые
репозитории сохраняются с сообщением. Записи, `runtime`, калибровочные данные,
глобальные Conda-окружения и отдельно установленный официальный FreeMoCap
не удаляются. Установщик откажется менять окружение работающего приложения.
Окружения, локальные инструменты и записи не включаются в Git.

## Проверка

```bash
cd server
./setup.sh --with-tests
source .venv/bin/activate
python -m pytest -q ../camera/test_camera_streamer.py test_visual_mocap_server.py
```

Проверки используют настоящие процессы FFmpeg и SkellySync, два локальных HTTP
узла, заданный сдвиг аудио/видео, докачку и замену калибровочного набора.
Физические камеры не нужны. Это проверка программного тракта; максимальную
скорость USB-камеры, диска и точность её аудиовидеозадержки проверяйте на одноплатнике.

Семафорный эксперимент в [src](src/README.md) сохранён отдельно; новый сервер
