# Сервер: управление камерами, получение и синхронизация видео

Основной сценарий: [README эксперимента](../README.md).
Сервер не вычисляет скелет, параметры калибровки или BVH. Результат —
синхронизированные видео для отдельно запущенного официального FreeMoCap.

```bash
./setup.sh --system-deps --clean-legacy
source .venv/bin/activate
python visual_mocap_server.py \
  --camera cam1=http://192.168.1.98:8081 \
  --camera cam2=http://192.168.1.112:8081 \
  --records "$HOME/mocap-recordings" --port 8080
```

Страница: http://192.168.1.90:8080. `--camera` повторяется для 2–8 узлов,
имя должно совпадать с `--name` на соответствующей камере. `--host` задаёт
интерфейс привязки (по умолчанию `0.0.0.0`). `--camera-token-file` позволяет
читать тот же секрет, что указан на камерах. Работа рассчитана на доверенную
локальную сеть, учётных записей в веб-интерфейсе нет.

```bash
sudo ufw allow from 192.168.1.0/24 to any port 8080 proto tcp
```

## Зависимости и миграция

Python 3.10–3.12, FFmpeg/ffprobe и Git. Окружение создаётся в `server/.venv`.
Единственная прямая Python-зависимость приложения — **SkellySync**. Его штатные
транзитивные зависимости (librosa, NumPy/SciPy, OpenCV и другие) устанавливаются
автоматически; это не пустое окружение. Веб-сервер работает на стандартной
библиотеке Python. Не нужны CUDA, PyTorch, ONNX Runtime, RTMlib, MediaMTX,
SkellyCam, FreeMoCap или Blender в этом окружении.

`setup.sh --clean-legacy` после успешной установки удаляет прежние окружения
`.venv-cpu`, `.venv-cuda`, `.venv-freemocap`, `.venv-calibration`, устаревшие
скачанные репозитории без локальных изменений и перечисленные кэши.
Записи и отдельно установленный официальный FreeMoCap сохраняются.
Все старые процессы нужно остановить до установки. Новое окружение использует
имеющийся совместимый Python; на сервере с Python 3.14 задайте установленный
3.12 через `--python /path/to/python3.12`.

## Данные

```text
<records>/
  current_calibration.json              # указатель на последний успешный набор
  takes/<id>/
    take.json                          # имя, тип, состояние, связь с калибровкой
    camera_manifests.json               # размеры и SHA-256 оригиналов
    raw_videos/<имя>.id-cam1.idx-0.mkv   # полные полученные оригиналы
    synchronized_videos/               # итог штатного SkellySync
    sync_result.json                   # сдвиги, число кадров, файлы и диагностика
    sync.log
```

При повторной выгрузке сверяются манифесты и SHA-256, частичные файлы
докачиваются. Синхронизация выполняется отдельным процессом, поэтому интерфейс
остаётся доступным. Одновременно выполняется один сеанс записи/выгрузки/
синхронизации. Сбой помечается ошибкой с сообщением, а исходники сохраняются.
Сервер после перезапуска показывает прерванные задания с возможностью повторить
выгрузку. Камеры должны оставаться настроенными на те же имена и адреса.

Для входных MKV отдельно подсчитываются видеопакеты: оценка OpenCV по общей
длительности контейнера может учитывать хвост звука и завышать число кадров.
Алгоритм задержек и обрезка остаются штатными в SkellySync.

Синхронизация определяется общим звуком, а не временем сетевых команд.
Рекомендуются короткие пробные записи с общим хлопком; для длинных проверяйте
ещё и конец записи на дрейф. SkellySync загружает аудио в память, поэтому расход
RAM и время зависят от длительности роликов. Полноразмерное видео обрабатывает
FFmpeg. Детали метода: [SkellySync](https://docs.freemocap.org/skellysync/).

Старый набор калибровки заменяется только после успешного нового результата.
Его файлы остаются на диске. На сервере не создаётся calibration TOML — его
должен рассчитать официальный FreeMoCap из соответствующего набора видео.

## HTTP API сервера

| Запрос | Данные / назначение |
|---|---|
| `GET /api/state` | Камеры, записи, текущий калибровочный набор |
| `GET /preview/cam1.jpg` | Превью через сервер с общим кэшем ≤1 запроса/с |
| `POST /api/start` | `{"name":"take_01","kind":"record"}` |
| `POST /api/stop` | `{"id":"...","upload":true}`; false оставляет файлы на камерах |
| `POST /api/upload` | `{"id":"..."}` — получить/докачать, затем синхронизировать |
| `GET /api/takes/<id>` | Полное состояние и результат задания |

POST: `Content-Type: application/json`. Для замены калибровки start дополнительно
содержит `replace_calibration: true` и `expected_calibration_id` текущего набора.
Без подтверждения сервер возвращает 409. Результат start/stop/upload — 202,
дальнейшее состояние проверяется через GET. Значение `synchronized_path`
доступно при `state == "ready"`; его можно передать вашему скрипту управления
официальным FreeMoCap.
