# Семафорный эксперимент: IMU + видеозахват

Отдельное настольное приложение по сценарию ER2026. Собственный костюм ESP32/IMU
остаётся первым источником; второй — BVH-поток из `../server/visual_mocap_server.py`.
В приложении есть общее OpenGL-окно двух скелетов, калибровка IMU по пяти позам,
окно оператора и окно участника, наборы слов SET01/SET02, таймер, парная запись и таблица результатов.

Исходники приложения находятся здесь. Словарь, наборы слов, анимация семафора,
мастер калибровки IMU и общий скелет экспорта переиспользуются из ER2026 внутри
этого же репозитория. SDK Noitom, Axis Studio и внешние клонированные каталоги не нужны.
Оригинальное приложение ER2026 сохраняет свой запуск и формат записей.

## Установка и запуск

На компьютере оператора нужен полный клон ImuMotionCapture, Python 3.11+ и
графическая сессия с OpenGL. Из корня репозитория:

```bash
cd scripts/Visual_IMU_compare/src
./setup.sh
.venv/bin/python main.py --source-ip 192.168.1.90
```

Setup создаёт собственное `src/.venv`, без sudo и без GPU-зависимостей.
Для создания venv нужен системный пакет `python3-venv`. На минимальном Linux
также должны быть установлены системные библиотеки Qt/OpenGL; при ошибке xcb
на Ubuntu/Debian проверьте `libxcb-cursor0`, `libxkbcommon-x11-0` и `libgl1`.
Фактические версии пакетов сохраняются в `runtime/requirements-resolved.txt`.
Можно использовать уже подготовленное окружение основного IMU-приложения:

```bash
python scripts/Visual_IMU_compare/src/main.py --source-ip 192.168.1.90
```

Путь к `main.py` может быть абсолютным; рабочая папка не влияет на записи.
Также поддерживается `python -m scripts.Visual_IMU_compare.src` из корня клона.
По умолчанию приёмник автоматически слушает **UDP 0.0.0.0:7001**.
`--manual-connect` оставляет запуск кнопкам Connect/Start в строке Visual.
`--source-ip` ограничивает входящий источник указанным IPv4; это адрес GPU-сервера.
Опциональный локальный порт управления экспериментом: `--event-port 5056`.

## Подключение GPU-сервера

Предположим, компьютер оператора имеет адрес **192.168.1.54**, а GPU-сервер —
**192.168.1.90**. На операторском компьютере при активном UFW:

```bash
sudo ufw allow from 192.168.1.90 to any port 7001 proto udp
```

На GPU-сервере RTSP-приёмник работает отдельным процессом, как описано в
[серверной инструкции](../server/README.md). Из `Visual_IMU_compare/server`:

```bash
.venv-cuda/bin/python visual_mocap_server.py \
  --device cuda:0 --host 0.0.0.0 --port 8080 \
  --camera 'cam1=rtsp://127.0.0.1:8554/cam1' \
  --camera 'cam2=rtsp://127.0.0.1:8554/cam2' \
  --bvh-target 192.168.1.54:7001 --bvh-transport udp
```

**Для настоящего BVH необходимы минимум две камеры, калибровка камер и
восстановленный 3D-скелет.** Одна камера с 2D-ключевыми точками не создаёт
эталон для парного эксперимента. При первом формировании скелета видеосерверу
нужны видимые плечи, таз, голова, локти, запястья, колени и лодыжки.

Для TCP задайте `--transport tcp` приложению и `--bvh-transport tcp` видеосерверу,
а правило UFW создайте для TCP. В обоих случаях **приложение слушает**, видеосервер
сам подключается к нему. `--port` меняет порт приёма BVH, а не RTSP или веб-порт.

## Порядок эксперимента

1. Дождитесь свежего потока Visual и красного скелета в окне захвата.
2. Для парного сравнения подключите ESP32, включите START и выполните
   пятиэтапную калибровку IMU: руки вниз → семафор А → Т → У → руки вниз.
3. При необходимости совместите направление систем в окне захвата.
4. Откройте **«Эксперимент…»** и нажмите **«Подтвердить калибровку видеозахвата»**.
   Это подтверждение оператора для уже откалиброванных камер; оно не заменяет
   калибровку камер в веб-интерфейсе. Оно привязано к текущим stream_id/skeleton_id.
5. Введите код участника, выберите SET01/SET02, экран участника и длительность
   (по умолчанию 300 с). Нажмите «Начать запись».
6. Показ запускается после свежих валидных кадров выбранных источников.
   Дождитесь окончания таймера, экспорта BVH и новой строки таблицы.

Галочки **«В датасет»** позволяют записывать пару либо только Visual/Custom.
При выборе только Visual IMU-костюм и его калибровка не требуются.
Потеря выбранного потока, неотслеживаемые руки/корпус, смена потока/скелета,
изменение направления или досрочный STOP делают запись неполной.
Свежесть по умолчанию — 500 мс; настройка `--stale-timeout-ms`.
Смена потока или повторное подключение требуют нового подтверждения калибровки.
Кнопки видимости сегментов влияют на отображение; экспорт проверяет все пять.

## Результаты

По умолчанию — `Visual_IMU_compare/records/`, отдельно от ER2026:

```text
records/
  records.csv
  application.log
  <время>_<участник>_<набор>_<id>/
    custom.bvh
    visual.bvh
```

CSV: `timestamp,subject_id,word_set_id,custom_bvh_path,visual_bvh_path`.
При одиночной записи путь невыбранного источника пустой. Успешная строка появляется
после проверки файлов; неполные записи остаются только в журнале.
`--records-dir` меняет каталог. Записи, окружения и runtime исключены из Git.

Пара экспортируется на одну временную сетку со SLERP, без экстраполяции,
с частотой не выше фактической частоты медленного источника. Оба файла используют
скелет ER2026: 14 суставов, 45 каналов, рост 1,70 м, метры, Y вверх, ZXY.
Сравниваются пять сегментов: спина, два плеча и два предплечья. Таз фиксирован;
перемещение человека и не измеряемые IMU ноги в сравнительный BVH не переносятся.
Это нормализованный экспорт для сравнения, а не копия входного BVH видеосервера.
Скрипты обработки ER2026 с колонкой `noitom_bvh_path` пока не адаптированы к этой таблице.

Временная шкала — локальный `perf_counter_ns` на приёме пакетов обоих источников.
Удалённое `timestamp_monotonic_s` не сравнивается с часами операторского ПК.
Это синхронизация по времени получения, которая не компенсирует задержку
камер/инференса/сети и не даёт аппаратной синхронизации с IMU.
Видеомодель оценивает направление конечности; вращение вокруг её оси не измеряется.

## Проверка без оборудования

Из `Visual_IMU_compare/server` запустите существующий синтетический источник:

```bash
.venv-cpu/bin/python visual_mocap_server.py --demo --device cpu \
  --bvh-target 127.0.0.1:7001
```

В другом терминале из `src`:

```bash
.venv/bin/python main.py --source-ip 127.0.0.1
```

Снимите Custom «В датасет», откройте эксперимент, подтвердите видеокалибровку,
выберите короткую длительность и проверьте `visual.bvh`. Эти данные синтетические.
Для тестов протокола, записи и интерфейса:

```bash
./setup.sh --with-tests
# Из корня репозитория:
QT_QPA_PLATFORM=offscreen scripts/Visual_IMU_compare/src/.venv/bin/python \
  -m pytest scripts/Visual_IMU_compare/src/tests -q -m 'not hardware'
```

Offscreen проверяет логику Qt; реальный OpenGL-контекст проверяется в графической сессии.

При переносе проверены 24 теста нового приложения и 40 проверок компонентов ER2026.
В графической X11-сессии проверены OpenGL и полный короткий семафорный цикл
с настоящим BVH-отправителем `visual_mocap_server.py --demo`: запись `visual.bvh`
и строка CSV успешно сохранены. Парный экспорт с IMU проверен синтетическими
измерениями; эксперимент с физическим костюмом и двумя камерами ещё предстоит.
