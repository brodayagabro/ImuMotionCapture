# Синхронный захват ESP32 и Noitom

Запуск из корня проекта:

```powershell
.venv\Scripts\python.exe scripts\ER2026\noitom_comparison\main.py
```

Подключите ESP32 и включите START; подключите Noitom и включите Start.
Галочки **«В датасет»** рядом с Custom и Noitom выбирают костюмы для записи.
Можно записывать оба одновременно, только Custom или только Noitom.
Невыбранный костюм можно не подключать и не калибровать; его обрыв не прерывает
запись. В папке сохраняются только выбранные BVH, в `records.csv` неиспользуемый
путь пустой. Выбор доступен между записями, после завершения сохранения.
Рядом с заголовком монитора UDP есть галочка **«Показывать пакеты»**.
По умолчанию она снята: текстовый монитор не обновляется. Приём данных,
калибровка и запись работают независимо от галочки. После включения появляются
только новые сообщения, без накопления пропущенных строк.
Кнопка **«Эксперимент…»** открывает новый демонстратор в том же приложении.
В нём задаются код испытуемого, набор SET01/SET02, калибровка и длительность.
По умолчанию запись длится 300 секунд. Результат — `custom.bvh`, `noitom.bvh`
и одна строка `records/records.csv`. Полный порядок действий и формат:
[инструкция демонстратора](../experiments/semaphore/README.md).

Калибровка поз: руки вниз → семафор А → Т → У → руки вниз,
по **1,5 секунды записи всех пяти датчиков**, 3 секунды подготовки на позу.
Отсчёт идёт по времени принятых полных измерений после проверки устойчивости;
число кадров зависит от частоты потока. Прогресс отображается как 0–1500 мс.
**«IMU-калибровка»** вызывает тот же CALIB, что основной визуализатор:
снять датчики, положить неподвижно локальной Z вверх, подтвердить диалог.
После ACK CALIB DONE снова нужна калибровка по позам.
Noitom калибруется в Axis Studio, затем оператор подтверждает это в демонстраторе.
Настройки и совмещение направления меняются между записями.
Галочки сегментов управляют отображением; парный BVH сохраняет пять измеряемых
сегментов обоих костюмов на одинаковом скелете: 14 суставов, 45 каналов, рост 1,70 м.
Отдельные кисти/пальцы исключены, таз фиксирован; голова и ноги не имеют собственных
измеряемых вращений. По умолчанию оба файла ограничены 50 Гц; предел меняется
в окне эксперимента. Приём Noitom остаётся на исходной частоте для интерполяции.
Экспорт и проверка выполняются последовательно в одном фоновом потоке, с полосой
прогресса в окнах захвата, оператора и участника.

У основного `pyqt-mocap` / `pyqt-mocap-gl` сохранён прежний одиночный BVH.
В экспериментальном окне одиночная запись скрыта: запуск — через демонстратор.

## Управление

Встроенный демонстратор вызывает тот же обработчик команд напрямую.
Отдельный демонстратор использует localhost TCP `--event-port` (5055; 0 отключает).
Команды: `status`, `calibrate`, `imu_calibrate`, `confirm_noitom_calibration`,
`start_recording`, `stop_recording`. Начало содержит `subject_id`, `word_set_id`,
`duration_s`, необязательный `export_fps` (50 по умолчанию, 1–100).
Остановка и heartbeat содержат `recording_session_id`.
`ready=true` только после валидных кадров обеих систем; ответ сообщает общий T0/T1.
По умолчанию потеря управления более 5 секунд делает запись неполной.
Автоматический срок записи контролируется отдельным потоком рекордера.
Метки отдельных букв/слов в этом сценарии отклоняются и не сохраняются.

`--records-dir` меняет корень хранения для тестов/переноса; прежнее имя параметра
`--recordings-dir` оставлено как совместимый алиас. По умолчанию всегда используется
абсолютный `scripts/ER2026/records`. Прежняя корневая папка `records` перенесена
сюда вместе с таблицей; относительные ссылки на BVH сохранены.
`recording.py`, `replay.py` и универсальный приёмник событий сохранены для чтения
и тестирования прежнего JSONL-формата; новый активный рекордер — `paired_recording.py`.
Для старой записи доступен `--replay <папка>`.

## Mocap API и Axis Studio

Используется официальный [Mocap API Noitom](https://github.com/pnmocap/MocapApi),
его C procedure tables с версиями и порядком вызовов из рабочего `demo/demo-py`.

SDK хранится отдельным локальным checkout и исключён из Git проекта. Версия,
использованная при проверке: `a62cb6dfc33fc74631c5732bd90f7a91bebe622a`.
Все текущие изменения отслеживаемых файлов SDK сохранены в
`patches/mocap-api-local.patch`: исправления Python demo/обёртки и изменённые
метаданные Python-пакета. Сгенерированные `build` и `__pycache__` не сохраняются.
Чтобы восстановить SDK в новой копии проекта, выполните из корня:

```powershell
git clone https://github.com/pnmocap/MocapApi.git scripts/MocapApi
git -C scripts/MocapApi checkout --detach a62cb6dfc33fc74631c5732bd90f7a91bebe622a
git -C scripts/MocapApi apply ../ER2026/noitom_comparison/patches/mocap-api-local.patch
```

В существующем checkout эти правки уже применены; повторно применять патч не нужно.
Отдельная установка Python wrapper не требуется. Локальная копия SDK уже
находится в `scripts/MocapApi`; заголовки и
бинарные файлы SDK экспериментальное приложение не меняет.

Пути по умолчанию:

| Платформа Python | Библиотека |
| --- | --- |
| Windows x64 | `scripts/MocapApi/demo/demo-py/MocapApi/mocap_api/lib/amd64/MocapApi.dll` |
| Linux x64 | `scripts/MocapApi/demo/demo-py/MocapApi/mocap_api/lib/x86_64/libMocapApi.so` |
| Linux ARM64 | `scripts/MocapApi/demo/demo-py/MocapApi/mocap_api/lib/arm64/libMocapApi.so` |

В первую очередь выбирается библиотека из `demo-py`; если её нет, используется
старый путь `bin/win32/x64/release` или `bin/linux/{x64,aarch64}`. В этом
репозитории Windows DLL из demo имеет версию `0.0.73.19a54f85`, а DLL из `bin` —
`0.0.17.a6e15748`. Живой поток проверен с версией из demo. Версия, полный путь
библиотеки, порт и режим приёма выводятся в мониторе и сохраняются в журнале записи.

Разрядность Python и библиотеки должна совпадать. Оставьте зависимости SDK рядом
с библиотекой либо в системном пути загрузчика. Любой другой путь можно передать
явно; отсутствие DLL выдаёт ошибку только в блоке Noitom:

```powershell
.venv\Scripts\python.exe scripts\ER2026\noitom_comparison\main.py --sdk-library "D:\MocapApi\MocapApi.dll" --port 7012
```

1. В Axis Studio подключите костюм и выполните его штатную калибровку.
2. Включите **BVH broadcasting**, направление — IP компьютера с приложением,
   UDP-порт **7012**, как в `demo-py` (или значение `--port`). Для разных компьютеров используйте
   LAN IP, а не `127.0.0.1`. Разрешите этот UDP-порт в межсетевом экране.
3. Выберите **Binary BVH**, включённые displacement/transformation и порядок
   вращений **XYZ**, как в `demo-py`. Другой порядок задаётся `--bvh-rotation ZXY`
   (поддерживаются все шесть порядков). Если Axis Studio настроен на другой формат, согласуйте его
   через `--bvh-format string` или `--bvh-format legacy` (старый бинарный header).
   Для этой итерации требуется поток BVH с иерархией и локальными вращениями.
4. В приложении **Noitom Connect** создаёт и настраивает SDK application;
   **Start** открывает приём, **Stop** закрывает приём, **Disconnect** освобождает
   SDK. Эти кнопки не запускают и не останавливают захват костюма в Axis Studio.
5. Для TCP: `--transport tcp --server 192.168.1.10 --port 7012`, где IP и порт
   соответствуют серверу вещания Axis Studio.

Если передаётся несколько актёров, используйте `--avatar-index N`. Без него
выбирается первый полученный актёр до следующего Disconnect. Индекс и имя актёра
проверяются во время записи; смена актёра делает запись неполной.

Приём повторяет `demo-py`: сначала `PollApplicationNextEvent(NULL, &count, app)`,
затем заполнение массива событий с заданным `size` каждого элемента. Одного
вызова с заранее выделенным массивом недостаточно: на живом потоке он возвращал
ноль событий. Вызовы SDK и копирование всех суставов выполняются в одном worker.
Режим записывается как `noitom.delivery_mode = "poll_latest"`. SDK может
объединять обновления **до передачи приложению**.
Повторные измерения не засчитываются. Сброс счётчика или смена аватара
прерывают запись; небольшие пропуски учитываются при оценке реальной частоты.
Разрывы более `--stale-timeout-ms` (по умолчанию 500 мс) запрещены.
Приложение не восстанавливает кадры, которых SDK не предоставил.
