# Семафорный эксперимент: один набор — одна запись

Запустите `.venv\Scripts\python.exe scripts\ER2026\main.py` из корня
проекта. Подключите ESP32, включите START, затем Noitom Connect и Start.
Кнопка **«Эксперимент…»** открывает окно оператора. Демонстратор также можно
запустить отдельно: `.venv\Scripts\python.exe -m scripts.ER2026.experiments.semaphore.main`.
Оба процесса должны работать на одном компьютере.

## Порядок работы

1. Введите код испытуемого, например `P001`.
2. Выберите `SET01` (существующий нижний набор) или `SET02` (верхний).
3. Нажмите «Калибровка»: руки вниз → семафор А → Т → У → руки вниз.
   На каждом этапе — **3 секунды подготовки и 1,5 секунды записи** пяти датчиков.
   После короткой проверки устойчивости окно отсчитывается по времени приёма
   полных кадров, независимо от их частоты; прогресс показывается в миллисекундах.
   При 50 кадрах/с весь мастер занимает около 24 секунд при правильном выполнении поз.
   Дубли и неполные кадры не продвигают запись. Проверки устойчивости, смены позы,
   возврата и минимального числа измерений сохранены; обрыв полных кадров более
   500 мс требует повторения этапа.
4. Выполните штатную калибровку Noitom в Axis Studio и нажмите
   «Noitom откалиброван в Axis Studio». При необходимости совместите
   направление костюмов в окне захвата до записи.
5. Выберите экран участника и зеркальный режим. Нажмите «Начать запись».
   «Частота BVH» задаёт общий предел экспорта (по умолчанию 50 кадров/с).
   Таймер и показ запускаются после получения новых валидных кадров обоих костюмов.
6. Через **300 секунд** рекордер автоматически завершает общий интервал,
   проверяет потоки и сохраняет пару BVH. Дождитесь 100% на полосе экспорта.
7. Выберите следующий набор и начните независимую запись. Можно заново
   откалибровать обе системы; обязательного обновления ID профилей нет.

«IMU-калибровка» — аппаратная команда CALIB, как в основном визуализаторе.
Она нужна для снятых неподвижных датчиков локальной Z вверх, с подтверждением
оператора. После неё необходима повторная калибровка по позам.

Состав наборов и словарь сохранены в `configs/lower_words.json`,
`configs/upper_words.json`, `semaphore_model.py`.
ID задаются в `configs/experiment.json` → `word_set_ids` и должны быть уникальными.
Порядок слов выбирается существующим способом перемешивания один раз на запись,
затем этот набор повторяется с начала. Цикл завершается после последней буквы
и возврата в нейтральную позу. Окончание общего времени записи имеет приоритет.
Глобального плана, распределения слов между сериями и разметки букв нет.

`recording_seconds` задаёт длительность (по умолчанию 300); её можно изменить
в окне оператора. `timing.hold` по умолчанию **1,6 с**, вдвое больше исходных 0,8 с.
`timing.transition` — независимый параметр (0,4 с), также доступный в окне.
`export_fps` — общий предел частоты BVH, по умолчанию 50 Гц; диапазон 1–100 Гц.
Полноэкранный режим участника: F11; Esc возвращает обычное окно.
Закрытие окна участника во время записи означает досрочную остановку.
`--debug` запускает только предпросмотр без файлов и строк таблицы.

## Файлы

Все записи находятся в `scripts/ER2026/records/`; ниже показано содержимое
относительно каталога ER2026:

```text
records/
  records.csv
  application.log
  20261012_143000_123456_P001_SET01_abcdef/
    custom.bvh
    noitom.bvh
```

Папка создаётся эксклюзивно; микросекунды и случайный суффикс защищают от коллизий.
`records.csv` содержит ровно пять колонок:

```csv
timestamp,subject_id,word_set_id,custom_bvh_path,noitom_bvh_path
```

Время — реальный общий T0 в ISO 8601 с часовым поясом. Пути относительны к `records`.
Строка добавляется после записи и повторной проверки обоих файлов; повторный
вызов индексации той же пары не создаёт дубль. Существующие строки не заменяются.
Таблица прежних успешных записей доступна в окне после перезапуска.

STOP, потеря потока, смена скелета, ошибки преобразования/диска и разрывы времени
не создают успешную строку. Причина записывается в `application.log`.
При ранней остановке не экспортируется законченная пара; при ошибке экспорта
могут остаться `.bvh.partial` или неиндексированная пара для диагностики.
Журнал хранит начало/результат, общий интервал, качество потоков и использованные
преобразования, без разметки слов и букв. После аварийного завершения процесса
незавершённый `recording` в журнале без строки CSV также не является успехом.
Данные текущей записи до экспорта находятся в памяти, поэтому при аварии
восстановление промежуточных измерений не гарантируется.

Прежняя корневая папка `records` перенесена сюда целиком, включая архивный
`records/semaphore`; содержимое файлов сохранено. Новый сценарий не пополняет
архивный формат. Архивные средства чтения оставлены в
`dataset.py`, `session_log.py`, `legacy_presenter.py` и `noitom_comparison/replay.py`.
Основной вход приложения больше не подключает планы, реестр проб или профили участников.
Каталоги записей и `output` остаются исключёнными из Git.

## Общая шкала BVH

Время кадра фиксируется на границе приёма данных на ПК (`time.perf_counter_ns`), до
обработки в интерфейсе. Это время поступления, а не синхронизированные часы IMU.
Приём, проверка свежести, калибровка и таймер демонстратора используют одну шкалу
`perf_counter`: на Windows это точный монотонный QueryPerformanceCounter.
Одинаковые метки одного потока объединяются с сохранением последнего кадра
и подсчитываются в `coalesced_timestamps` журнала; время искусственно не сдвигается.
Уменьшение метки по-прежнему останавливает запись с указанием потока и величины скачка.
T0 — более поздний из первых валидных кадров потоков после команды старта;
для другого потока сохраняются измерения, окружающие T0.
T1 = T0 + заданная длительность. Кадр сразу после T1 нужен только для интерполяции
на границе и не увеличивает длительность записи. Ожидание ограничено 500 мс.

Частота ограничивается фактической частотой более медленного источника:
минимум средней частоты, медианной частоты каждого потока, настройки частоты ESP32
и выбранного предела «Частота BVH» (50 Гц по умолчанию). Число интервалов округляется вниз; поэтому частота
может быть дробной. Оба файла получают один массив времён от T0 до T1 включительно,
одинаковые `Frames` и `Frame Time`. Например, 300 с при 10 Гц — 3001 кадр,
времена 0…300 с; время кадра i = timestamp + i × Frame Time.

Ориентации интерполируются SLERP по кратчайшей дуге с согласованием знаков.
В пределе очень малых углов используется нормализованная линейная комбинация.
Приём Noitom сохраняет исходную частоту: промежуточные пакеты нужны для SLERP,
затем оба потока пересчитываются на одну сетку. Экстраполяция запрещена.
Перед экспортом проверяются покрытие T0/T1, порядок времён, конечность значений
и максимальные промежутки между валидными измерениями. По умолчанию разрыв
более **500 мс** делает запись неполной (`--stale-timeout-ms`). Небольшие пропуски
уменьшают оценку реальной частоты; невалидные/повторные измерения не засчитываются.

Оба BVH используют один скелет `comparison_14_joints_v1`: **14 суставов,
45 каналов, рост 1,70 м**, одинаковые имена, родители, OFFSET и End Site.
Единицы — метры, Y вверх, углы ZXY. Вращаются пять измеряемых сегментов:
спина, два плеча и два предплечья. Кисти и пальцы не имеют отдельных суставов:
предплечья заканчиваются End Site в запястьях. Положение таза фиксировано,
голова и ноги не имеют собственных измеряемых вращений в обоих файлах.

Собственная система использует C·q·K. Noitom сначала собирает мировые вращения
по исходной иерархии, затем переносит их на те же пять сегментов через
существующий NoitomAdapter с учётом осей костей и выбранного направления.
Исходные размеры Noitom и его перемещение по комнате не переносятся в BVH.
Визуальное сглаживание и галочки видимости не меняют экспортируемые измерения.
Низкоуровневый IMU-фильтр не изменён. Смена аватара, иерархии или направления
во время записи запрещена. Сведения о формате и частоте сохраняются в журнале.
Уже сохранённые BVH прежнего формата автоматически не конвертируются.

Один фоновый поток последовательно готовит, записывает и проверяет оба файла.
Обработка разбита на небольшие порции, преобразования матриц выполняются пакетно.
Интерфейс показывает процент и текущий этап; 100% означает сохранённую пару
и строку в таблице. При ошибке процент не подменяется успешным завершением.

Абсолютная синхронизация физических измерений ограничена задержками сети и SDK:
равная шкала получения пакетов не устраняет аппаратную задержку костюма.
Noitom SDK может объединять кадры до их получения приложением.

## Проверки

`python -m pytest -q -m "not hardware"` проверяет математику, оба экспортёра,
300-секундный интервал на управляемых часах, отсутствие фиктивного успеха при
ошибках, индекс, повтор записи и цикл слов. Интеграционный тест включает реальные
локальные UDP/TCP-сокеты, два Qt-окна, синтетический Noitom, автоматический экспорт,
ранний STOP и повторное открытие таблицы. Полный пятиминутный экспорт проверяется
с таймером Qt: интерфейс продолжает отвечать, прогресс растёт, работает один
экспортирующий поток. Новый общий скелет пока проверен на синтетических данных.
