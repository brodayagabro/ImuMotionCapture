# ER2026: обработка, ручная разметка и классификатор поз

Пайплайн работает с индексом `scripts/ER2026/records/records.csv`. Исходные
BVH читаются без изменения. Разметка сохраняется рядом с BVH в папке записи;
отчёты и модели — в `scripts/ER2026/output/`. Обе папки исключены из Git. Код обработки не требует
SDK Noitom, подключения костюмов или запуска сборщика.

Результаты исследования текущих файлов: [DATASET_REPORT.md](DATASET_REPORT.md).

## Быстрый запуск

Команды выполняются из корня репозитория. Для окружения анализа:
`.venv\Scripts\python.exe -m pip install -e ".[analysis,notebook,classification,dev]"`.

### Ноутбуки

[motion_capture_analysis.ipynb](motion_capture_analysis.ipynb) содержит аудит BVH,
таблицы RMS/P95 и корреляций, графики ошибок по времени, подробный разбор
выбранной пары и наложение поз. Параметры записи,
сустава и участка времени задаются в начале. Обработка ограничена системами
захвата движений; вспомогательные TXT не читаются.

```powershell
.venv\Scripts\python.exe -m jupyterlab scripts/ER2026/processing/motion_capture_analysis.ipynb
```

Выполните ячейки сверху вниз. Таблицы и PNG/SVG сохраняются в
`output/motion_notebook/`. Ручная разметка выполняется отдельно командой
`processing annotate`, приведённой ниже.

[semaphore_classification.ipynb](semaphore_classification.ipynb) читает готовые
метки из `records/<recording_id>/<recording_id>.json` и сравнивает семь методов: Dummy, ближайший
центроид, kNN, логистическую регрессию, линейный/RBF SVM и случайный лес.
Источник по умолчанию — Noitom. Проверяются два набора признаков: средние
направления костей рук относительно спины и средние со стандартными отклонениями.

```powershell
.venv\Scripts\python.exe -m jupyterlab scripts/ER2026/processing/semaphore_classification.ipynb
```

Параметры окна, обрезки границ, моделей, признаков и проверки находятся в начале.
В режиме `auto` откладываются целые участники, при единственном участнике —
записи, а при единственной записи — временные блоки с удалением близких обучающих
удержаний. Неоднозначные ID участников требуют явной карты `SUBJECT_MAP`.
Окна одного удержания не делятся между обучением и проверкой; масштабирование
обучается заново в каждой обучающей части. Параметры моделей фиксированы, без
автоматического подбора. Проверка внутри сессии не измеряет перенос на новых людей.

Основные метрики считаются по удержаниям, дополнительные — по окнам. Показаны
баланс классов, буквы без обучающих примеров, матрица ошибок и ошибочные интервалы.
Результаты, признаки, состав частей и хеши данных сохраняются в
`output/classification_experiments/`. Сохранение выбранного sklearn Pipeline
в `final_model.joblib` включается параметром `FIT_FINAL_MODEL`; по умолчанию выключено.
Это оценка букв внутри размеченных удержаний; непрерывное обнаружение поз и
переходов отдельно не оценивается. Сравнение конфигураций служит для выбора модели,
после которого нужен отдельный окончательный тест на новой записи.

### Командная строка

```powershell
# Проверка файлов, расчёт ошибок и статические графики
.venv\Scripts\python.exe -m scripts.ER2026.processing analyze --plots

# Ручная разметка существующих записей
.venv\Scripts\python.exe -m scripts.ER2026.processing annotate

# Сравнение костюмов дополнительно на подтверждённых позах
.venv\Scripts\python.exe -m scripts.ER2026.processing analyze --reviewed-labels --plots

# После появления подтверждённых меток хотя бы двух классов
.venv\Scripts\python.exe -m scripts.ER2026.processing train

# Экспорт проверенных интервалов захвата движений
.venv\Scripts\python.exe -m scripts.ER2026.processing export-labels
```

Все команды имеют `--help`. `--records`, `--labels`, `--output` позволяют
выбрать другие каталоги. По умолчанию JSON ищется рядом с BVH; `--labels <каталог>`
явно включает прежний общий каталог `<каталог>/<recording_id>.json`.
В обоих ноутбуках `LABELS_ROOT = None` означает расположение рядом с BVH.
`--plots` требует matplotlib; без него таблицы и
отчёт рассчитываются с NumPy/SciPy. Приложение разметки использует имеющиеся
PyQt6 и pyqtgraph, работает без OpenGL.

## 1. Сравнение систем

`analyze` создаёт:

- `audit.json`: валидация каждого источника, SHA-256, число кадров, частота,
  длительность, возможные замирания/скачки, выдержки из журнала, отдельный
  список неиндексированных и пустых каталогов и проверка старого архива протокола;
- `inventory.csv`: сводная таблица источников;
- `comparison.csv`: метрики отдельных сегментов и точек;
- `comparison_10s.csv`: RMS/mean/median/P95 в непересекающихся окнах примерно 10 с;
- `comparison_intervals.csv`: те же метрики по подтверждённым интервалам
  с ID/буквой/границами, если передан `--reviewed-labels` или `--labels`;
- `report.md`: читаемый отчёт;
- `comparison.png`, `comparison.svg`: графики при `--plots`.

BVH читается с восстановлением мировой кинематики в порядке каналов.
Поддерживается общий скелет `comparison_14_joints_v1` в метрах; другая геометрия
не конвертируется молча. Для пары требуются одинаковые иерархия, OFFSET,
End Site, Frames и Frame Time. Тестовая запись старого формата остаётся в
аудите как неподдерживаемая. Ошибка одного файла не прерывает аудит остальных.
ZIP-копии и архив `records/semaphore` не добавляются в основной датасет.

В каждой паре считаются следующие величины:

| frame / kind | Смысл |
|---|---|
| `world / rotation_deg` | Геодезическая разность мировых вращений спины, плеч и предплечий |
| `spine / rotation_deg` | Разность вращений рук относительно собственной спины каждого костюма |
| `parent / rotation_deg` | Локальные вращения относительно родителя; для предплечья — относительно плеча |
| `spine / direction_deg` | Угол между направлениями костей; не чувствителен к осевому вращению сегмента |
| `anatomical / elbow_flexion_deg` | Разность угла между плечом и предплечьем; 0° означает прямую руку |
| `world, spine / position_mm` | Ошибка положений левого/правого локтя и запястья |

`LeftForeArm` и `RightForeArm` в позиционных метриках — локти, их `.end` —
запястья. Геометрия у костюмов общая; это ошибка реконструированных точек,
а не независимые измерения положения маркеров. Кисти/пальцы, ноги и голова
не считаются отдельными измеренными степенями свободы.

**Выравнивание спины выполняется в каждом кадре**:

```text
R_body,j = R_world,spineᵀ · R_world,j
p_body,j = R_world,spineᵀ · (p_world,j − p_world,spine)
angular_error = acos(clamp((trace(R_customᵀ · R_noitom) − 1) / 2))
position_RMS = sqrt(mean(||p_custom − p_noitom||²))
```

Таким образом, body-метрики исключают общее вращение туловища и его ошибку;
они не оценивают точность самой спины. Для этого сохранён вариант `world`.
Углы Эйлера напрямую не вычитаются. Для каждой ошибки выводятся RMS, mean,
median, P95. Pearson считается отдельно по x/y/z положений и направлений,
а для сгибания локтя — по самому углу. Постоянный сигнал даёт пустое значение
в CSV / `null` в JSON. `bias` сгибания имеет знак Custom минус Noitom.

Основные числа используют **исходную общую сетку и все кадры**, включая
переходы. Диагностика задержки ищет максимум корреляции скоростей направлений
в пределах ±0,5 с. Положительный lag означает, что движение Noitom приходит
позже Custom. Эта оценка не применяется к данным и не является независимой
калибровкой задержки. Малое движение, периодичность и сетка кадров ограничивают
её точность. Нет DTW, экстраполяции или подгонки вращений по тестовым позам.

После разметки `analyze --reviewed-labels` дополнительно считает ошибки
для каждого подтверждённого интервала буквы или `NEUTRAL` в парных записях.
`TRANSITION`, `BAD`, `UNKNOWN` и интервалы короче трёх кадров не входят в эту
таблицу. Основные метрики полных записей сохраняются отдельно; графики
`comparison_10s.csv` помогают локализовать проблемные участки. Noitom здесь —
система сравнения, а не доказанный абсолютный эталон.

## 2. Ручная разметка

Верхний список выбирает запись с Noitom. Обе проекции показывают только
Noitom: спереди и сбоку. График скорости, подсказки букв и поиск устойчивых
положений также используют Noitom. На фронтальной проекции анатомическая
левая рука участника находится справа на экране. Начало координат — спина.

Рабочий порядок:

1. Выберите нужную запись в верхнем списке.
2. Воспроизведите движение: Space, выбор скорости 0,25/0,5/1/2, ползунок
   или щелчок по графику времени. Перед выбором интервала приостановите просмотр.
3. Выделите устойчивое удержание жёлтой областью на графике или числовыми
   полями начала/конца. Не включайте переходы между позами.
4. Выберите букву либо `NEUTRAL`, `TRANSITION`, `BAD`, `UNKNOWN` и нажмите
   «Подтвердить и сохранить» / Ctrl+S. Только это действие создаёт метку.
5. «Следующее устойчивое положение» / N ищет ещё не размеченный участок
   с максимальной скоростью четырёх сегментов менее 18°/с, обрезает по 0,1 с
   и оставляет участки от 0,5 с. Границы нужно проверить и при необходимости
   изменить: медленный переход тоже может оказаться кандидатом.
6. Для редактирования выберите строку таблицы, измените поля и подтвердите.
   «Новый интервал» снимает выбор строки. Есть удаление и Ctrl+Z до переключения
   записи. Каждый шаг сохраняется; предыдущая версия остаётся в `.json.bak`.

Подсказки букв — ближайшие эталонные направления **плеч**, с числом градусов
до идеальной позы. Они не учитывают контекст слова и не превращаются в
обучающие метки автоматически. Е/Э совпадают в существующем словаре; при
сомнении между ними без контекста используйте `UNKNOWN` или комментарий.
Невозможно отличить одинаковые физические позы только по кинематике.

Сохранение: `records/<recording_id>/<recording_id>.json`, схема версии 1.
Это папка исходных `noitom.bvh` и `custom.bvh`, указанная в `records.csv`;
текущая рабочая папка запуска не влияет на расположение JSON. Существующий JSON
с таким именем загружается автоматически. Резервная копия `.json.bak` хранится рядом.
Старые файлы из `output/annotations/` можно перенести в соответствующие папки
записей без переименования либо продолжать использовать через `--labels`.
Интервалы задаются как **[start_s, end_s)** относительно нулевого кадра BVH,
не пересекаются и ограничены длительностью записи. Незанятые участки не имеют
метки. Хранятся исходная буква, признак проверки, комментарий, метаданные
записи и SHA-256 каждого BVH. Изменение источника блокирует использование
старой разметки. Подтверждение в GUI означает ручной просмотр оператором,
а не автоматическую проверку правильности буквы.
Новые и отредактированные интервалы отмечаются `annotation_source="noitom"`.
Для парных записей сохраняются хеши обеих систем для последующего сравнения.

Рекомендуется сначала разметить небольшую выборку разных букв каждого набора,
согласовать границы устойчивых удержаний, затем пройти записи целиком. Часть
интервалов стоит независимо пересмотреть вторым оператором. Для проверки
поз из плохого Custom используйте Noitom, но не выводите букву только из того,
что участнику предположительно показывал демонстратор: ошибки выполнения возможны.

## 3. Базовый классификатор

`train` использует только подтверждённые интервалы. `TRANSITION`, `BAD`,
`UNKNOWN` исключаются, `NEUTRAL` становится классом при наличии примеров.
Е и Э объединяются в `Е/Э`, исходные буквы остаются в экспорте. Никаких
показателей качества на текущих неразмеченных данных пока нет.

Признаки: четыре единичных направления костей в системе спины — плечи и
предплечья слева/справа. В окне 250 мс считаются средние и стандартные
отклонения координат: 24 признака без разрывов углов 0/360°. Перед нарезкой
от удержания убирается по 100 мс. Шаг окон — около 125 мс, округляется к кадрам.
Источник по умолчанию Noitom; `--source custom` обучает отдельную модель.
Смешивания источников одной пары как независимых примеров нет.

Модель — ближайший центроид класса после стандартизации, с нижней границей
масштаба признака 0,05. Это воспроизводимый базовый вариант без sklearn.
Он позволяет проверить качество разметки перед усложнением модели. Обучение
не меняет калибровку и не устраняет дрейф исходного костюма.

Проверка оставляет целого участника вне обучения; стандартизация заново
обучается внутри каждого fold. Если один человек записан под разными ID,
передайте JSON-словарь `--subjects`: все его записи должны попасть в одну группу.
Если встречаются и `P001`, и `P001_mio`, без явной карты обучение с группировкой
по участнику остановится, чтобы не выдать проверку на том же человеке за
обобщение. Пример карты: [subjects.example.json](subjects.example.json).
Перед использованием подтвердите соответствие кодов реальным участникам.

```powershell
.venv\Scripts\python.exe -m scripts.ER2026.processing train --subjects scripts/ER2026/processing/subjects.example.json

# Отдельный вопрос: перенос между записями, без заявления о новом человеке
.venv\Scripts\python.exe -m scripts.ER2026.processing train --group recording
```

Нужно хотя бы два класса. При единственной независимой группе модель
сохранится, но оценка будет `not_evaluated`. Для нескольких групп выводятся
accuracy, balanced accuracy, macro-F1, confusion matrix, результаты каждого
fold и классы теста, которых не было в его обучающей части. Эти метрики
поконные: окна одного удержания зависимы, доверительные интервалы для
независимых проб по ним строить нельзя.

Результаты: `output/classifier/model.npz` (без pickle), `evaluation.json`,
`windows.csv`, `validation_predictions.csv`. Манифест содержит хеши BVH и
разметки. `windows.csv` связывает признаки с исходным интервалом и группой.

```powershell
.venv\Scripts\python.exe -m scripts.ER2026.processing predict `
  scripts/ER2026/records/20261021_130127_935575_P001_mio_SET01_012733/noitom.bvh `
  --output scripts/ER2026/output/predictions.csv
```

`predict` выдаёт метки непересекающихся окон примерно по 250 мс и расстояние
до центроида. Расстояние — **не вероятность**. У модели пока нет надёжного
отказа на неизвестной позе: переход тоже получит ближайшую букву. Предсказания
сохраняются отдельно с `reviewed=False` и не импортируются в ручную разметку.
Для последующего реального времени можно использовать `feature`, `fit`,
`predict` из `classifier.py` с тем же порядком направлений и длиной окна.

## 4. Экспорт разметки движений

`export-labels` сохраняет ID записи/интервала, букву, пригодность для обучения,
относительные секунды BVH и подсказки абсолютного времени. Интервалы имеют
границы [start_s, end_s); переходы, BAD и UNKNOWN сохраняются с признаком
исключения из обучения. Экспорт проверяет хеши исходных BVH.

Текущий пайплайн анализирует только захват движений. Другие модальности
не читаются и не включаются в отчёт.

## Проверки и источники метода

```powershell
$env:QT_QPA_PLATFORM='offscreen'
.venv\Scripts\python.exe -m pytest scripts/ER2026/processing/tests -q -m "not hardware" `
  --basetemp=scripts/ER2026/output/processing_test_local `
  -o cache_dir=scripts/ER2026/output/pytest_cache
```

Тесты проверяют порядок неперестановочных вращений при чтении BVH,
инвариантность верхней части скелета к общему вращению после выравнивания,
переход +179°/−179°, несовместимые сетки, перекрытия/хеши меток,
проверку по группам, отсутствие выдуманной модели без меток, полный путь
обучение → предсказание, экспорт меток и сохранение/редактирование/отмену в GUI.

Порядок вращений соответствует
[SciPy Rotation.from_euler](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.transform.Rotation.from_euler.html):
заглавные `ZXY` означают intrinsic rotations. Принцип разделения зависимых
примеров по участникам описан в
[документации групповой перекрёстной проверки](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data).
Базовый классификатор команды `processing train` реализован на NumPy.
Для отдельного ноутбука сравнения методов используется scikit-learn из extra `classification`.
