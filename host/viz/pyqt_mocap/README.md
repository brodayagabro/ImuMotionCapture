# PyQt MPU6050 motion capture

Отдельное приложение для приёма пяти MPU6050 по UDP, отображения скелетной
модели и комплексной калибровки установочных осей. Объёмный mesh корпуса не
используется: поза показана линиями сегментов и точками суставов.

## Установка и запуск

Из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m pyqt_mocap
```

Editable-установка нужна потому, что исходный пакет хранится в `host/viz`.
Она также добавляет консольную команду `pyqt-mocap`. Прямой launcher без
установки пакета можно вызвать так:

```bash
python host/viz/pyqt_mocap/run.py
```

На Ubuntu/Debian для Qt 6 нужен системный пакет:

```bash
sudo apt install libxcb-cursor0
```

## Запись и экспорт BVH

По умолчанию запись выключена. После подключения, запуска потока и калибровки
нажмите **Начать запись** на основной панели. После движений нажмите ту же
кнопку, которая переключится на **Остановить запись**, затем **Сохранить BVH…**.
Те же действия доступны в меню **Файл**. Счётчик записи виден в строке состояния.
При отмене сохранения или ошибке записи данные остаются в памяти; при
закрытии окна или начале новой записи приложение предлагает их сохранить.
STOP и отключение останавливают запись, сохраняя уже принятые данные.

Файл содержит откалиброванные движения аватара, включая сглаживание и
компенсацию дрейфа модели. FPS фиксируется по настройке частоты потока ESP32
на момент начала записи, независимо от FPS отрисовки. Время берётся из
приёма UDP на компьютере; нерегулярные отсчёты приводятся к равномерной сетке
удержанием предыдущей позы. Пропуски пакетов выглядят как удержание позы.
Изменение конфигурации и запуск калибровки останавливают запись.

Единицы BVH — метры, вертикальная ось — Y, порядок вращений — ZXY.
Рост в нейтральной позе — 1,70 м от стоп до верхнего End Site головы.
Пропорции масштабируются равномерно; стопы стоят на Y=0. В импортёре,
использующем метры, задайте масштаб 1. BVH не хранит обозначение единиц:
старые записи в сантиметрах требуют масштаба импорта 0,01. Для применения
нового масштаба начните новую запись; существующие файлы не меняются.
Кисти имеют явную длину 18 см (ненулевой `End Site`), чтобы импортёр не
достраивал их по длине предплечья. Отдельные движения кистей не измеряются:
они следуют за предплечьями. Голова и стопы также имеют ненулевые окончания.
При импорте в Blender включите **Update Scene FPS** и **Update Scene Duration**:
экспортёр сохраняет частоту в `Frame Time`, но сам BVH не может переключить
FPS сцены Blender. Масштаб импорта новых записей — **1**.
Таз и ноги неподвижны: система измеряет только корпус и руки, перемещение
человека не восстанавливается. Отключённые сегменты соответствуют опорной
позе приложения. Формат имеет расширение `.bvh` (не `.bhv`).

## Направления датчиков

Система координат окна: X — вправо, Y — вперёд, Z — вверх. Цвета
направляющих стандартные: X красная, Y зелёная, Z синяя.

| Сегмент | Оси в положении «руки вперёд» | Начальное преобразование |
|---|---|---|
| `shoulder.L`, `forearm.L` | X вправо, Y к пальцам, Z вверх | `+X +Y +Z` |
| `shoulder.R`, `forearm.R` | X влево, Y от пальцев к локтю, Z вверх | `-X -Y +Z` |
| `spine` | X вправо, Y вниз, Z вперёд | `+X +Z -Y` |

Имена `spine`, `shoulder.L`, `forearm.L`, `shoulder.R`, `forearm.R`
оставлены такими же, как в Blender-проекте. Преобразования можно вручную
изменить через **Правка → Настройки**.

Скелет по умолчанию показан спереди. Поэтому анатомическая левая рука человека
с подписями `shoulder.L` и `forearm.L` находится справа для наблюдателя, а
анатомическая правая рука с подписями `*.R` — слева.

Во вкладке **Датчики** у каждого сегмента есть флажок **Смотреть**. Отключённый
датчик не обрабатывается и не участвует в ожидании N/T-калибровки. По умолчанию
`spine` (канонический ID 2) выключен, а четыре датчика рук включены. Оси
позвоночника X/Y/Z при этом остаются на скелете как приглушённая опорная
система и помечаются текстом «опорные оси»; это не означает приём живых данных
от отключённого датчика.

## Комплексная калибровка

Кнопка **КАЛИБРОВКА** предлагает мастер поз, отдельную семафорную калибровку
XZ и **Полную IMU**. Отдельные «Только A-поза» и «Гироскоп + A-поза» убраны.
Полная IMU отправляет `CALIB` после подтверждения: модули должны быть сняты,
лежать неподвижно локальной Z вверх. Начальная нейтрализация потока сохранена.

1. Подключитесь к ESP32 и нажмите **START**.
2. Откройте **КАЛИБРОВКА → A → T → вперёд → P → A** или одноимённый
   пункт меню **Устройство**.
3. Нажмите **Начать калибровку** один раз. Мастер показывает анимированный
   переход и неподвижный пример целевой позы, даёт 5 секунд на подготовку,
   затем автоматически записывает 5 секунд. Последовательно выполняются:
   A-позу с руками вниз, T-позу, обе руки прямо вперёд, P-позу (ладони вместе
   перед грудиной), затем снова A-позу
   с руками вниз. В A-позе локти разогнуты, ладони обращены к бёдрам.
   На надписи «Запись — не двигайтесь» удерживайте позу; переходите к следующей
   только при новом отсчёте подготовки. Весь цикл занимает около 50 секунд.
   Если данных недостаточно, мастер останавливается и предлагает повторить
   текущий этап. **Отмена** прекращает калибровку без применения результата.
4. Мастер усредняет только новые UDP-кадры, проверяет направления,
   уточняет перестановки осей, вычисляет непрерывную sensor-to-segment поправку
   по переходам A → T и A → «руки вперёд», затем уточняет оси предплечий по
   направлениям в T-позе, руках вперёд и P-позе. В P-позе верхние части рук
   и локти прижаты к корпусу; предплечья направлены вверх и к центру,
   внутренний угол локтя около 45° (прямая рука — 180°).
   Повторная A-поза проверяет возврат
   к исходному направлению, используется для оценки стационарного дрейфа и
   становится свежей нейтральной позой после завершения мастера.
5. Сохраните результат через **Файл → Сохранить профиль калибровки**.

Профиль JSON содержит IP, порт, частоты, соответствие датчиков сегментам,
преобразования и непрерывное согласование осей, оценку дрейфа и данные пяти
поз. Импорт выполняется через **Файл → Импорт профиля калибровки**. После
импорта нужно один раз
принять свежую A-позу: мировая система DMP может измениться после перезапуска
контроллера.

Завершающая A-поза мастера обновляет нейтральный отсчёт. Предупреждение о высокой
остаточной ошибке показывается при значении выше 45°.

MPU6050 не имеет магнитометра, поэтому абсолютный курс со временем физически
может уходить. Компенсация уменьшает стационарный дрейф, измеренный в A-позе,
но не заменяет магнитометр. Если курс заметно ушёл, повторите весь
пятиэтапный мастер. Профили прежних версий 1–4 остаются доступны для импорта;
новые профили сохраняются в версии 5. Для использования P-позы пройдите мастер
заново. Калибровка уточняет ориентации сегментов, но не измеряет длины рук:
точное совпадение кистей зависит также от пропорций аватара.

## Семафорная калибровка XZ

Откройте **КАЛИБРОВКА → Семафорная XZ** или одноимённый пункт меню
**Устройство**. Один запуск автоматически записывает начальную A-позу,
один круг **А → У → Ж → Е → Д**, затем конечную A-позу. На каждом из
7 этапов отводится 5 секунд на переход и 5 секунд на запись: всего около
70 секунд. При недостатке новых кадров можно повторить этап.

Направления задаются относительно примера в мастере: левая рука слева
(-X), правая справа (+X), вверх +Z; корпус не поворачивать.

| Буква | Левая рука | Правая рука |
|---|---|---|
| А | Вниз-влево, 45° | Вниз-вправо, 45° |
| У | Вверх-влево, 45° | Вверх-вправо, 45° |
| Ж | Горизонтально влево | Вверх-вправо, 45° |
| Е | Вниз | Вверх-вправо, 45° |
| Д | Горизонтально влево | Плечо вниз-влево через корпус, 45°; локоть слегка согнут |

Д зеркальна прежней Б. В остальных буквах локти прямые. Угол сгиба правого локтя в Д не задан:
его изображение условно, данные правого предплечья этой буквы сохраняются,
но исключаются из расчёта и оценки ошибки. Не нужно добиваться показанного
на рисунке точного угла локтя.

Расчёт начинает с усреднения осей вращения и затем минимизирует ошибки
направлений сегментов по пяти буквам, уточняя нормаль плоскости движения
(две степени свободы). Это учитывает, что скручивание руки вокруг её оси
меняет ось результирующего кватерниона, не меняя направления сегмента.
Перестановки осей сохраняются;
неопределимое по одной плоскости вращение согласования вокруг её нормали
не переоценивается: выбирается минимальная поправка к действующему профилю.
Для полноценного согласования в 3D сначала используйте обычный мастер поз.
Это калибровка ориентаций, не длин сегментов и не абсолютных координат кистей.

Конечная A-поза не участвует в подборе поправки: она проверяет возврат,
задаёт свежую нейтраль и оценку дрейфа. Остаточная ошибка направлений
вычисляется именно относительно этой конечной нейтрали, как у аватара.
При расхождении начальной и конечной A-поз более 30° результат не применяется;
выше 15° мастер рекомендует повторить калибровку. Ошибка возврата, семь поз
и тип `semaphore_xz` сохраняются в JSON-профиле; формат преобразований
совместим с обычным мастером. Повторяемость букв по одному кругу не оценивается.

## Настройки и протокол

В **Правка → Настройки** на лету меняются IP/UDP-порт, частота потока ESP32,
FPS интерфейса, активные датчики, соответствие датчиков сегментам и осевые
преобразования. При смене адреса приложение переподключается; при смене
частоты отправляет `SET_RATE <Гц>`.

Поддерживаются строки `FRAME ...` и `Q <id> <w> <x> <y> <z>`, а также
ответы `ACK`, `STATUS`, `SENSOR`, `PONG` и `ERR`. Кнопки **START**, **STOP**
и **КАЛИБРОВКА** сохранены.

## Состав каталога

- `mpu_udp_viewer.py` — главное окно и UDP-приёмник;
- `run.py` — прямой launcher каталога;
- `mocap_core.py` — протокол, кватернионы, дрейф и модель человека без Qt;
- `calibration.py` — расчёт пяти этапов и JSON-профили;
- `semaphore_calibration.py` — плоскость XZ и проверка возврата в A-позу;
- `guided_dialog.py` — пошаговый мастер;
- `window_calibration.py` — импорт, экспорт и подключение мастера к окну;
- `tests/` — автономные тесты.

Зависимости и настройки pytest находятся в корневом `pyproject.toml`.

Основные тесты без дисплея запускаются из корня репозитория:

```bash
python -m pip install -e ".[dev]"
pytest
```

GUI smoke-тест с локальным UDP-сокетом запускается отдельно:

```bash
QT_QPA_PLATFORM=offscreen pytest -m gui \
  host/viz/pyqt_mocap/tests/test_gui_udp_smoke.py
```
